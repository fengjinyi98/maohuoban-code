# 媒资可审计可追溯存储目标文档

- 更新时间：2026-07-03
- Goal：所有用户头像、用户背景、宠物头像、宠物背景、相册、动态、商品和后续业务媒资统一使用可追溯对象路径、完整元数据和独立业务引用模型，为后续内容审核、合规监管和低成本复用打基础。
- 执行方式：TDD 分层落地；先固化共享路径契约，再迁移既有 profile / pet 上传链路，后续按相册、动态、商品和审核能力分切片推进。

---

## 1. 当前结论

| 项 | 结论 |
|---|---|
| 物理存储 | 同一张图片只应在 RustFS/S3 中保存一份物理对象，动态和相册通过业务引用独立关联 |
| 业务边界 | 动态媒体和相册照片生命周期独立；删除动态不删除相册照片，删除相册照片不删除动态媒体 |
| 路径契约 | 所有媒资对象统一使用 `media/users/{user_id}/yyyy/mm/{asset_id}/<fixed-name>` |
| 原图文件名 | 原图统一命名为 `original.{ext}`，不在对象路径里保留用户原始文件名 |
| 标准派生图 | 缩略图固定 `thumbnail.png`，主题色固定 `theme-color.json` |
| 元数据要求 | 所有可展示媒资必须持久化 `mime_type`、`byte_size`、`sha256_hex`、`width`、`height`；派生图必须持久化尺寸或用途 metadata |
| 审核准备 | 审核系统应基于 `media_assets.id`、对象路径、hash、上传人、业务引用和审计事件追溯，不依赖业务表路径推断 |

## 2. 目标边界

## 2.1 本目标期必须完成

| 范围 | 目标 |
|---|---|
| 共享路径构建器 | 在 `maohuoban-media-storage` 提供统一对象 key 生成能力 |
| profile 上传迁移 | 用户头像和用户背景原图使用统一路径 |
| pet 上传迁移 | 宠物头像、背景、相册照片等 pending 上传原图使用统一路径 |
| 标准派生图迁移 | 图片缩略图和主题色派生图使用统一固定文件名 |
| 元数据不回退 | 路径迁移后继续保留尺寸、MIME、大小和 hash 元数据 |
| 文档化边界 | 固化相册/动态独立业务引用、物理对象共享和审核追溯原则 |

## 2.2 本目标期暂不做

| 暂不做 | 原因 |
|---|---|
| 完整 `media_objects` 拆表 | 先用现有 `media_assets` 承载物理对象和资产身份，后续再拆 hash 去重层 |
| 动态发布相册联动实现 | 需要独立设计 `posts` / `post_media_assets` 和事务接口 |
| 商品媒资迁移 | 商品模块媒资尚未进入当前链路，本目标先建立基础设施契约 |
| 审核服务接入 | 当前先准备可审计数据底座，审核队列、机审、人审后续单独落地 |
| 历史对象迁移 | 新上传走统一路径；旧对象的后台迁移和校验单独立项 |

## 3. 项目内依据

| 层 | 文件 / 事实 | 依据 |
|---|---|---|
| 媒资表 | `maohuoban-rust/migrations/0007_pet_profile_media.sql` | `media_assets` 已有 `mime_type`、`byte_size`、`sha256_hex`、`bucket`、`object_key`、`width`、`height`、`status`、`delete_after` |
| 宠物上传 | `maohuoban-rust/crates/maohuoban-pet-infrastructure/src/postgres/repository/media_commands/preparation.rs` | 原先路径包含 `pet-media/pending` 和 usage kind，绑定后路径语义会变旧 |
| 用户上传 | `maohuoban-rust/crates/maohuoban-profile-infrastructure/src/postgres/repository/media.rs` | 原先路径为 `users/{user_id}/profile/{kind}/{asset_id}/{filename}`，和宠物路径不一致 |
| 相册关系 | `maohuoban-rust/crates/maohuoban-pet-infrastructure/src/postgres/pet_album_repository/commands.rs` | `pet_album_assets` 通过 `asset_id` 引用媒体资产，移除时只写 `removed_at` |
| GC | `maohuoban-rust/crates/maohuoban-media-gc-worker/src/lib.rs` | 只有 `cleanup_pending` 且 `delete_after` 到期的资产会被物理删除 |

## 4. 推荐数据模型

```text
media_assets
  -> one physical object in RustFS/S3
  -> stable metadata: mime, bytes, sha256, width, height

post_media_assets
  -> post business reference to asset_id

pet_album_assets
  -> album business reference to asset_id

cleanup scanner
  -> checks all active references
  -> queues physical deletion only when active_refs == 0
```

短期继续使用 `media_assets` 作为资产和物理对象的统一表。后续需要 hash 去重时再拆：

```text
media_objects 物理对象与 hash
media_assets 用户资产身份与审核状态
business refs 动态、相册、头像、商品等引用
```

## 5. 对象路径契约

| 对象 | 路径 |
|---|---|
| 原图 | `media/users/{user_id}/yyyy/mm/{asset_id}/original.{ext}` |
| 缩略图 | `media/users/{user_id}/yyyy/mm/{asset_id}/thumbnail.png` |
| 主题色 | `media/users/{user_id}/yyyy/mm/{asset_id}/theme-color.json` |
| Live Photo 配对视频 | `media/users/{user_id}/yyyy/mm/{asset_id}/paired-video.{ext}` |
| 视频封面帧 | `media/users/{user_id}/yyyy/mm/{asset_id}/video-cover-frame.png` |

路径字段含义：

| 字段 | 作用 |
|---|---|
| `user_id` | 审计上传归属和监管取证 |
| `yyyy/mm` | 运维分区、批量巡检和生命周期管理 |
| `asset_id` | 和数据库资产、审核任务、业务引用精确关联 |
| 固定文件名 | 避免泄露用户原始文件名，降低路径歧义 |

## 6. 元数据契约

| 字段 | 要求 |
|---|---|
| `mime_type` | 必填，响应和审核均使用 |
| `byte_size` | 必填，用于大小限制、计费和异常检测 |
| `sha256_hex` | 必填，用于去重、追溯和违规复核 |
| `width` / `height` | 图片类媒资必须存在；视频类由封面帧或转码 metadata 补齐 |
| derivative metadata | 缩略图必须记录尺寸；主题色必须记录颜色；视频封面帧必须记录尺寸 |

## 9. 不变约束

| 约束 | 说明 |
|---|---|
| 单一数据流 | 上传先形成 `media_assets`，业务模块只引用 `asset_id` |
| 业务引用独立 | 动态、相册、头像、商品的删除语义各自独立 |
| 物理删除延迟 | 只有所有有效引用归零后才允许进入 GC |
| 不泄露原文件名 | 原始用户文件名只作为数据库审计字段，不进入对象 key |
| 元数据必备 | 任何路径迁移都不能丢失尺寸、大小、MIME、hash |
| 审核可追溯 | 审核事件必须能从 `asset_id` 反查对象、上传人、业务引用和处理记录 |

## 10. 风险

| 风险 | 处理 |
|---|---|
| 旧路径对象仍存在 | 数据库记录保留旧对象 key；新上传走新路径，旧数据迁移单独处理 |
| 新业务引用遗漏 | 动态、商品、医疗记录接入时必须新增业务引用表和引用归零测试 |
| `media_assets` 同时承担物理对象和资产身份 | 短期接受；hash 去重和审核状态复杂化后拆 `media_objects` |
| 引用归零判断漏业务表 | 后续新增统一 media reference scanner，所有业务引用必须注册 |
