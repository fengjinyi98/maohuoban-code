# 宠物档案媒体上传补齐目标文档

- 更新时间：2026-06-17
- Goal：补齐添加宠物页媒体保存闭环，将头像和背景上传升级为 multipart，接入 Toast 反馈，治理 AsyncImage 远程图片缓存能力，并将首页宠物 mock 收敛到单只宠物。
- 执行方式：新开 worktree，TDD 小步提交；每完成一个可验证切片提交一次。

## 1. 当前结论

| 项 | 当前状态 | 目标判断 |
|---|---|---|
| 创建宠物接口 | 已存在 `POST /api/v1/pets` | 后端已实现基础创建接口 |
| 媒体上传接口 | 已存在头像、背景图片、背景视频三个接口 | 后端已实现独立媒体上传接口 |
| 添加宠物媒体保存 | 添加页可本地预览头像和背景草稿，但创建成功后未串联上传 | 需要补齐创建后上传编排 |
| 上传协议 | 当前 iOS / Rust 均为 JSON + base64 | 需要升级为 `multipart/form-data` |
| Toast | `MHBToastPresenter` 和全局 `.mhbToast()` 已存在 | 宠物写入链路需要接入 Toast |
| AsyncImage 缓存 | iOS 27+ 官方 `AsyncImage` 支持按传输协议缓存下载数据 | 可沉淀远程图片基础组件 |
| 宠物 mock | 首页 mock 仍保留 `pet-mochi` 和 `pet-tangyuan` 两只宠物 | 暂时只保留一只 mock 宠物 |

## 2. 目标边界

| 范围 | 必须完成 |
|---|---|
| 添加宠物保存 | 用户在添加页选择头像或背景后，点击保存应先创建宠物，再使用返回的宠物 ID 上传头像和背景 |
| multipart 上传 | 头像、背景图片、背景视频上传接口改为 multipart，避免 base64 带来的体积膨胀和内存浪费 |
| 媒体可追溯 | 继续保留现有 `media_assets`、`media_bindings`、`media_derivatives`、`media_cleanup_jobs` 和审计逻辑 |
| Toast 反馈 | 创建、上传、部分失败、完全成功都通过 Toast 明确反馈 |
| 添加页 UI/UX | 保持当前添加页、头像预览、背景预览、裁剪、视频选择和 Liquid Glass 体验 |
| Mock 收敛 | 首页宠物 owner mock 只保留一个宠物；未开发的 state 卡片、相册故事等 mock 可以继续保留 |
| AsyncImage 治理 | 创建统一远程图片组件，优先使用 iOS 27 原生缓存能力 |

## 4. 推荐数据流

| 步骤 | 行为 | 成功标准 |
|---|---|---|
| 1 | 添加页保存基础档案 | `POST /api/v1/pets` 返回新宠物 ID |
| 2 | 如果存在本地头像草稿，上传头像 multipart | 返回 `pet.avatar` 媒体资产和 active binding |
| 3 | 如果存在本地背景图片草稿，上传背景图片 multipart | 返回 `pet.background.image` 媒体资产、缩略图和主题色派生 |
| 4 | 如果存在本地背景视频草稿，上传背景视频 multipart | 返回 `pet.background.video` 媒体资产、封面帧和主题色派生 |
| 5 | 任一媒体上传失败 | 宠物档案保留，Toast 告知“档案已创建，部分媒体保存失败” |
| 6 | 全部成功 | Toast 告知保存成功，刷新首页和宠物档案数据 |

## 7. Toast 目标

| 场景 | Toast |
|---|---|
| 未登录 | warning：请先登录 |
| 创建宠物成功且无媒体 | success：宠物档案已创建 |
| 创建宠物成功且媒体全部成功 | success：宠物档案和媒体已保存 |
| 创建宠物成功但部分媒体失败 | warning：档案已创建，部分媒体保存失败 |
| 创建宠物失败 | danger：使用后端或本地校验错误 message |
| 媒体派生处理中 | warning 或 neutral：背景派生资源处理中 |

实现建议：

| 方案 | 取舍 |
|---|---|
| Store 注入 `MHBToastPresenter` | 复用 AuthViewModel 现有模式，命令式反馈集中在 Store |
| View 使用 `.onChange(of: store.phase)` 调 Toast | Toast 属于 View 生命周期事件，Store 保持纯状态模型 |

推荐使用第二种：创建 `PetWriteToastBridge` 或 View modifier，监听 `PetWritePhase` 并调用 `MHBToastPresenter`。这样网络状态仍在 Store，Toast 副作用落在 SwiftUI 事件边界。

## 8. AsyncImage 目标

Apple 官方文档本地副本：

| 项 | 链接 |
|---|---|
| 官方 Markdown 副本 | [AsyncImage.md](../../references/apple/swiftui/AsyncImage.md) |
| 原始来源 | `https://developer.apple.com/tutorials/data/documentation/swiftui/asyncimage.md` |

基于官方文档结论：

| 能力 | iOS 27+ 状态 |
|---|---|
| 下载缓存 | `AsyncImage` 会按传输协议缓存下载数据 |
| 自定义请求 | 支持 `AsyncImage(request:scale:transaction:content:)` |
| 缓存策略 | 通过 `URLRequest.cachePolicy` 和 timeout 控制 |
| URLSession | 支持 `.asyncImageURLSession(_:)` 为层级内 `AsyncImage` 指定 session |

项目治理目标：

| 任务 | 文件建议 | 要求 |
|---|---|---|
| 远程图片组件 | `maohuoban/maohuoban/Infrastructure/RemoteImage/MHBRemoteImage.swift` 或 DesignSystem 组件目录 | 封装占位、失败、缩放、缓存策略 |
| 头像组件迁移 | `PetProfileEditMediaComponents.swift`、`PetProfileAvatarPreviewScreen.swift` | 宠物头像远程加载走统一组件 |
| 首页头图迁移 | `HomeImmersivePetHeaderSection.swift` | 远程头图走统一组件，保留本地 asset fallback |
| session 配置 | App 根或图片组件 | iOS 27+ 使用 `.asyncImageURLSession(_:)` 配置共享图片 session |

## 12. 不变约束

| 约束 | 说明 |
|---|---|
| UI/UX | 不改变当前已确认的添加档案、编辑档案、预览、裁剪、Liquid Glass 和 sheet 行为 |
| MVVM | View 只转发事件；网络、上传、状态转换进入 Store / Repository |
| SwiftUI 副作用 | Toast 通过事件边界触发，不在同步渲染路径写状态 |
| 媒体可清理 | multipart 升级不能破坏旧媒体替换和 GC worker 清理机制 |
| 删除恢复 | 宠物软删除恢复窗口和媒体延迟清理策略保持不变 |
| mock 边界 | 只清理宠物档案主链路相关 mock，未开发业务模块 mock 保留 |

## 13. 风险

| 风险 | 处理 |
|---|---|
| multipart 大文件占用内存 | 限制 body size，视频上传后续可升级直传或分片 |
| 创建成功但媒体失败 | 保留宠物档案，Toast 提示部分失败，用户可进入编辑档案重试 |
| 旧 JSON 上传测试失效 | 同步更新 iOS 和 Rust 契约测试 |
| AsyncImage 缓存依赖 HTTP header | RustFS / CDN 后续需要配置合理 `Cache-Control` |
| 删除第二只 mock 影响多宠切换开发态 | 多宠切换测试使用真实后端测试数据或专用 fixture |
