# 登录系统设计文档

- 文档版本：v0.4
- 更新时间：2026-06-13
- 适用范围：iOS 登录前端、Rust 后端认证服务、PostgreSQL、Redis、诊断观测、端到端测试
- 关联设计稿：`docs/html/maohuoban-login-design.html`
- 关联约束：`AGENTS.md`

## 1. 目标

登录系统需要承接手机号验证码登录、密码登录、忘记密码、后续第三方登录接入、双 token 会话、多设备扩展和准确 toast 反馈。

当前阶段完成：

| 目标 | 说明 |
|---|---|
| 手机号验证码登录 | 开发环境验证码固定为 `123456`，仍走真实 challenge、Redis TTL、限流与消费逻辑 |
| 密码登录 | 使用手机号 + 密码登录，密码只保存安全 hash |
| 忘记密码 | 独立账号恢复边界，不和登录用例混在一起 |
| 第三方登录 | 本期实现 provider 边界和 TODO 响应，后续接入微信 / Apple 时不改主会话层 |
| 双 token | access token 短时有效，refresh token 长期滑动有效 |
| 多设备 | 以 `device_sessions` 作为设备会话边界，保留设备列表、踢下线、可信设备扩展 |
| Toast 反馈 | 后端错误返回稳定 `code` 与中文 `message`，前端声明式消费并显示 toast |

## 2. 边界划分

后端使用 Rust workspace crates 承载分层边界，根产品 crate 只做装配和运行时入口。

| Crate | 层级 | 代码位置 | 职责 |
|---|---|---|---|
| `maohuoban-auth-domain` | Domain | `maohuoban-rust/crates/maohuoban-auth-domain` | 认证领域模型、错误类型、OAuth provider、refresh 解析状态 |
| `maohuoban-auth-application` | Application | `maohuoban-rust/crates/maohuoban-auth-application` | 登录用例编排、端口 traits、验证码 / 密码 / refresh 流程 |
| `maohuoban-auth-infrastructure` | Infrastructure | `maohuoban-rust/crates/maohuoban-auth-infrastructure` | PostgreSQL repository、Redis OTP store、Argon2、JWT、refresh token hash |
| `maohuoban-auth-http` | Interface | `maohuoban-rust/crates/maohuoban-auth-http` | axum router、HTTP DTO、统一响应、错误 code/message 映射 |
| `maohuoban_rust` | Composition | `maohuoban-rust` | 配置读取、迁移执行、服务装配、测试支撑、main 启动 |

| 模块 | 层级 | 职责 | 禁止混入 |
|---|---|---|---|
| `auth` | 后端 Application / Interface | 登录入口、签发 token、刷新 token、退出登录 | 验证码发送细节、密码 hash 实现 |
| `verification` | 后端 Domain / Infrastructure | 验证码 challenge、Redis 存储、限流、校验 | 用户创建、session 签发 |
| `credentials` | 后端 Domain / Infrastructure | 密码 hash、密码校验、密码更新 | 登录流程编排 |
| `account_recovery` | 后端 Application / Interface | 忘记密码、验证码恢复、重置密码 | 登录状态持久化 |
| `oauth` | 后端 Interface / Application | 微信 / Apple provider 抽象、TODO 响应 | 手机号验证码实现 |
| `device_sessions` | 后端 Domain / Infrastructure | refresh token、设备维度 session、撤销与轮换 | UI 展示逻辑 |
| `AuthFeature` | iOS Feature | 登录页、验证码页、忘记密码页、ViewModel 状态流 | 网络底层实现、token 持久化细节 |
| `AuthData` | iOS Data | DTO、API Client、TokenStore、Keychain | SwiftUI 视图状态 |
| `Toast` | DesignSystem / App 基础设施 | 声明式 toast 展示与后端 message 消费 | 登录业务判断 |

## 3. 后端接口契约

统一响应结构：

```json
{
  "success": true,
  "code": "ok",
  "message": "操作成功",
  "data": {}
}
```

失败结构：

```json
{
  "success": false,
  "code": "auth.invalid_code",
  "message": "验证码错误，请重新输入",
  "data": null
}
```

| 接口 | 方法 | 用途 | 成功 message |
|---|---|---|---|
| `/api/v1/auth/phone/code` | `POST` | 发送登录验证码 | `验证码已发送` |
| `/api/v1/auth/phone/verify` | `POST` | 验证码登录 / 自动注册 | `登录成功` |
| `/api/v1/auth/password/login` | `POST` | 密码登录 | `登录成功` |
| `/api/v1/auth/refresh` | `POST` | refresh token 轮换 | `登录状态已刷新` |
| `/api/v1/auth/logout` | `POST` | 退出当前设备 | `已退出登录` |
| `/api/v1/account-recovery/code` | `POST` | 发送忘记密码验证码 | `验证码已发送` |
| `/api/v1/account-recovery/reset-password` | `POST` | 重置密码 | `密码已重置` |
| `/api/v1/auth/oauth/wechat` | `POST` | 微信登录预留 | `微信登录暂未开放` |
| `/api/v1/auth/oauth/apple` | `POST` | Apple 登录预留 | `Apple 登录暂未开放` |

## 4. Token 与 Session

| 对象 | 形态 | 默认时效 | 存储 | 说明 |
|---|---|---|---|---|
| Access Token | JWT / PASETO 风格签名 token | 15 分钟 | iOS 内存，必要时 Keychain 读取恢复 | 调业务接口 |
| Refresh Token | opaque random token | 180 天滑动有效 | iOS Keychain；服务端只存 hash | 刷新 access token |
| Device Session | PostgreSQL 行记录 | 跟 refresh token 一致 | PostgreSQL | 支持多设备、踢下线、风控 |

刷新策略：

| 场景 | 行为 |
|---|---|
| App 冷启动 | 读取 refresh token，调用 `/auth/refresh`，成功后进入已登录态 |
| Access token 过期 | API Client 自动 refresh 一次，再重放原请求 |
| Refresh 成功 | 轮换 refresh token，旧 token hash 进入短 grace 窗口 |
| Refresh token 重放 | 识别 previous refresh token hash，撤销当前 session，返回 `auth.refresh_reused` |
| 主动退出 | 撤销当前 `session_id` |
| 密码重置 | 撤销该用户所有旧 session，当前恢复 session 可按产品策略保留 |

## 5. 数据库设计

本项目使用独立数据库 `maohuoban`。默认库 `fengjinyi` 中旧项目表清理后不再作为毛伙伴后端运行库。

| 表 | 关键字段 | 索引策略 |
|---|---|---|
| `users` | `id`, `status`, `created_at`, `last_login_at` | `status` 普通索引 |
| `user_identities` | `user_id`, `provider`, `identifier`, `verified_at` | `unique(provider, identifier)` |
| `password_credentials` | `user_id`, `password_hash`, `algorithm`, `updated_at` | `unique(user_id)` |
| `device_sessions` | `id`, `user_id`, `device_id`, `refresh_token_hash`, `previous_refresh_token_hash`, `expires_at`, `revoked_at` | `unique(refresh_token_hash)`, `unique(previous_refresh_token_hash)`, `index(user_id, revoked_at)` |
| `auth_audit_events` | `user_id`, `event_type`, `metadata`, `created_at` | `index(user_id, created_at desc)` |

性能原则：

| 主题 | 设计 |
|---|---|
| 登录查找 | 手机号登录先查 `user_identities(provider='phone', identifier=phone)` |
| Refresh | 只按 `refresh_token_hash` 查一行，命中后原子更新 token hash |
| 多设备列表 | 按 `user_id + revoked_at` 查询，避免扫全表 |
| 审计日志 | 写入追加型，后续可按月分区 |

## 6. Redis 设计

Redis 只放短期状态，不承载用户永久身份。

| Key | TTL | 说明 |
|---|---|---|
| `maohuoban:otp:{challenge_id}` | 5 分钟 | 保存验证码 hash、手机号、purpose、尝试次数 |
| `maohuoban:otp:phone:{purpose}:{phone}` | 60 秒 | 单手机号发送间隔 |
| `maohuoban:otp:ip:{purpose}:{ip}` | 60 秒 | 单 IP 发送间隔 |
| `maohuoban:refresh:grace:{token_hash}` | 30 秒 | 后续多端弱网容错预留，当前实现优先重放识别与撤销 |

开发环境：

| 项 | 值 |
|---|---|
| 验证码 | 固定 `123456` |
| 发送器 | `NoopOtpSender`，只记录 diagnostics 事件 |
| 安全边界 | 仍校验 TTL、限流、尝试次数、一次性消费 |

## 7. iOS 前端设计

登录前端遵循 MVVM 和单向数据流。

| 目录 | 职责 |
|---|---|
| `Features/Auth/Domain` | 登录状态、表单值对象、错误码映射协议 |
| `Features/Auth/Data` | DTO、Repository、API Client 适配 |
| `Features/Auth/Presentation` | SwiftUI 页面、ViewModel、子视图 |
| `Infrastructure/Networking` | HTTP Client、请求签名、自动 refresh |
| `Infrastructure/Security` | Keychain TokenStore、DeviceIdStore |
| `Infrastructure/Toast` | 后端 message 到 DesignSystem Toast 的适配 |
| `maohuobanUITests` | 登录端到端 UI 自动化，覆盖验证码登录、退出、第三方 TODO toast、忘记密码、系统保存密码弹窗、密码登录 |

页面状态：

| 页面 | 状态 |
|---|---|
| 登录页 | `phone`, `password`, `mode`, `agreementAccepted`, `isSubmitting` |
| 验证码页 | `challengeId`, `maskedPhone`, `digits`, `resendAfter`, `isVerifying` |
| 忘记密码页 | `phone`, `challengeId`, `newPassword`, `isSubmitting` |

可访问性与 UI 测试约定：

| 元素 | identifier | 说明 |
|---|---|---|
| 手机号输入 | `auth.phoneInput` | 验证码登录和密码登录共用 |
| 验证码输入区域 | `auth.verification.codeBoxes` | 以可点击 Button 语义暴露，视觉仍为 6 位格子 |
| 验证码提交 | `auth.verifyCodeButton` | 完成手机号验证码登录 |
| 退出登录 | `home.logoutButton` | 作为登录成功后的可操作验证点 |
| 忘记密码入口 | `auth.recoveryButton` | 密码模式下可见 |
| 忘记密码验证码 | `auth.recovery.codeInput` | 重置密码验证码 |
| 系统保存密码弹窗 | `以后` / `Not Now` | XCUITest 在重置密码后关闭系统 Sheet，再等待密码登录按钮可命中 |

Toast 策略：

| 来源 | Toast 类型 |
|---|---|
| `success=true` 且需要反馈 | success |
| `4xx` 业务错误 | warning |
| `401` 登录失效 | danger，并切回登录 |
| 网络超时 / 服务不可用 | danger |
| 表单本地校验 | warning |

## 8. 观测与诊断

后端接入现有 `maohuoban_diagnostics`：

| 事件 | 类型 | metadata |
|---|---|---|
| 验证码发送 | `EventKind::Identity` | `purpose`, `phone_masked`, `result` |
| 登录成功 | `EventKind::Identity` | `method`, `user_id`, `device_id` |
| 登录失败 | `EventKind::Identity` / `Error` | `method`, `reason`, `ip_masked` |
| Refresh 轮换 | `EventKind::Identity` | `session_id`, `rotated=true` |
| Logout | `EventKind::Identity` | `user_id`, `device_id` |
| 密码重置 | `EventKind::Identity` | `user_id`, `phone_masked` |
| 数据库 / Redis 耗时 | `Performance` | `operation`, `duration_ms` |

当前后端同步写入 `auth_audit_events`，运行时存在 diagnostics 句柄时额外记录 `EventKind::Identity`。

敏感字段必须经过 SDK 隐私策略脱敏：`authorization`, `password`, `token`, `access_token`, `refresh_token`, 手机号文本。

## 11. 本地与真机联调地址

| 项 | 当前值 | 说明 |
|---|---|---|
| iOS 默认 API 地址 | `http://192.168.2.2:8080` | 使用 Mac 局域网 IP，模拟器和真机共用同一个开发入口 |
| Rust 默认监听地址 | `0.0.0.0:8080` | 允许同一局域网内的真机访问；可通过 `SERVER_BIND_ADDR` 覆盖 |
| 自动化 E2E 地址 | `http://127.0.0.1:18080` | HTTP E2E 和 iOS UI E2E 固定使用本机测试后端 |
| 真机联调地址 | `http://192.168.2.2:8080` | 后端监听所有网卡后供同一局域网真机访问 |
| iOS 本地网络权限 | `NSLocalNetworkUsageDescription` | 真机首次访问局域网服务时用于系统权限弹窗说明 |
| Debug HTTP 访问 | `NSAppTransportSecurity.NSAllowsArbitraryLoads = true` | 当前阶段用于本地 HTTP 后端联调；后续生产环境切换 HTTPS 后收紧 |
