# 认证与个人资料 E2E 运行手册

- 文档版本：v0.9
- 更新时间：2026-06-23
- 适用范围：Rust 后端认证/Profile 契约、HTTP E2E、iOS 认证 UI E2E
- 当前入口：`scripts/e2e/auth_login.sh`、`maohuobanUITests/MaohuobanAuthUITests`

---

## 1. 核心结论

自动化 E2E 统一使用本机测试后端 `http://127.0.0.1:18080`、测试数据库 `maohuoban_test`、Redis DB 15。

| 项 | 固定值 |
|---|---|
| HTTP E2E 默认地址 | `http://127.0.0.1:18080` |
| UI E2E 默认地址 | `http://127.0.0.1:18080` |
| 测试数据库 | `maohuoban_test` |
| 测试 Redis | `redis://127.0.0.1:6379/15` |
| 测试 Redis 前缀 | `maohuoban:e2e:auth` |
| iOS 目标设备 | `iPhone 17 Pro, OS=27.0` |

真机局域网联调继续使用 `http://192.168.2.2:8080` 这类局域网地址；自动化 E2E 固定走 `127.0.0.1:18080`，减少误连开发库和端口冲突。

## 4. HTTP E2E

默认运行：

```bash
cd /Users/fengjinyi/Developer/maohuoban-code
scripts/e2e/auth_login.sh
```

显式覆盖运行：

```bash
BASE_URL=http://127.0.0.1:18080 \
DATABASE=maohuoban_test \
scripts/e2e/auth_login.sh
```

脚本覆盖范围：

| 链路 | 断言 |
|---|---|
| 验证码发送 | 响应 `success=true`，`message=验证码已发送` |
| 验证码登录 | 响应 `message=登录成功`，返回 `phone_masked`、`has_password=false`、`user.profile` |
| 账号安全读取 | `GET /api/v1/account/security` 返回 `account.security_loaded`、`has_password=false` |
| 首次设置密码 | `POST /api/v1/account/password` 不需要验证码，成功返回 `account.password_set`、`has_password=true` |
| 重复设置密码 | 已设置密码后再次 `POST /api/v1/account/password` 返回 `account.password_already_set` |
| 修改密码验证码 | `POST /api/v1/account/password/change-code` 返回 `challenge_id` 和 `message=验证码已发送` |
| 修改登录密码 | `PATCH /api/v1/account/password` 需要旧密码、`challenge_id`、验证码、新密码和确认密码 |
| 修改密码错误 | 旧密码错误返回 `account.current_password_invalid` 和可展示 `message` |
| 登录设备列表 | `GET /api/v1/account/devices` 返回 `account.devices_loaded`、当前设备标记和 `session_id` |
| 登录设备详情 | `GET /api/v1/account/devices/{session_id}` 返回 `account.device_loaded` 和设备详情 |
| 当前设备移除 | `DELETE /api/v1/account/devices/{session_id}` 移除当前设备返回 `account.current_device_remove_forbidden` |
| 其他设备移除 | 移除其他设备返回 `account.device_revoked`，被移除设备 refresh 返回 `auth.refresh_invalid` |
| Profile 读取 | `GET /api/v1/profile/me` 返回 `profile.loaded`、`message=个人资料已加载` |
| Profile 更新 | `PATCH /api/v1/profile/me` 更新昵称、简介、性别展示和生日，返回 `profile.updated`、`message=个人资料已更新` |
| Profile 编辑策略 | 读取和更新响应返回 `display_name_edit_policy`、`bio_edit_policy` |
| Profile 超限 | 昵称 30 天 5 次、简介 30 天 3 次，超限返回 429 业务码和可展示 `message` |
| Profile 隐私 | 登录响应和 Profile 响应均不包含 `badges`、`join_sequence` |
| 头像展示 | 默认 `avatar_presentation.sex=unknown`、`sex_visibility=hidden` |
| Refresh | 新 token 可用，旧 refresh token 重放返回 `auth.refresh_reused` |
| 忘记密码 | 重置后 `message=密码已重置` |
| 密码登录 | 返回 `has_password=true`，Profile 摘要保持一致 |
| 退出登录 | 返回 `message=已退出登录` |
| 第三方 TODO | Apple OAuth 返回 `auth.oauth_todo` |

脚本要求所有响应包含非空 `message`，供前端 Toast 消费。新增认证/Profile E2E 断言时继续复用 `expect_toast_message`。

脚本执行清库前会先跑 preflight：

| 检查项 | 失败处理 |
|---|---|
| `node` / `curl` | 安装命令行依赖，或修正当前 shell 的 `PATH` |
| `PSQL` | 默认使用 Postgres.app 18，可通过 `PSQL=/path/to/psql` 覆盖 |
| `DATABASE` | 默认 `maohuoban_test`，不可连接时先创建或修正变量 |
| 本地后端 | 访问 `LEGAL_PROBE_PATH=/api/v1/legal-documents/user_agreement`，不可访问时先启动 E2E 后端 |

preflight 通过后才会执行 `TRUNCATE`，避免服务未启动或变量指向错误时先清理测试库。

### 4.1 Profile 媒体上传 HTTP E2E 接入约束

用户头像和主页背景上传已并入 `scripts/e2e/auth_login.sh` 默认断言路径。

| 接口 | 断言 |
|---|---|
| `POST /api/v1/profile/me/avatar` | HTTP `201`、`code=profile.avatar_uploaded`、`message=头像已保存`、`data.avatar.asset_id/url/width/height` 非空 |
| `POST /api/v1/profile/me/cover` | HTTP `201`、`code=profile.cover_uploaded`、`message=主页背景已保存`、`data.cover.asset_id/url/width/height` 非空 |
| `GET /api/v1/profile/me` | 上传后重新读取，`data.avatar` / `data.cover` 与上传响应保持一致 |
| 内容读取 | `GET data.avatar.url`、`GET data.cover.url` 返回对应图片内容 |

脚本辅助函数：

```bash
request_multipart_image_authorized() {
  local path="$1"
  local access_token="$2"
  local file_path="$3"
  curl --silent --show-error \
    --header "authorization: Bearer $access_token" \
    --request POST \
    --form "file=@${file_path};type=image/png" \
    --form "source_client=ios" \
    "$BASE_URL$path"
}
```

测试图片在脚本运行时生成到临时目录，执行结束清理：

```bash
avatar_file="$(mktemp -t maohuoban-avatar.XXXXXX.png)"
cover_file="$(mktemp -t maohuoban-cover.XXXXXX.png)"
```

生成图片优先使用仓库内 fixture；缺少 fixture 时使用本机可用工具生成 16x16 PNG。不要把真实用户图片放入 E2E 目录。

### 5.2 账号密码 UI E2E 接入约束

账号密码页已经接入 `CurrentUserStore -> SettingsPasswordStore -> SettingsPasswordRepository -> /api/v1/account/*` 数据流。

| 项 | 约束 |
|---|---|
| 入口 | 登录后从 `我的 -> 设置 -> 账号与安全 -> 登录密码` 进入 |
| 当前状态 | 页面初始密码状态从 `CurrentUserStore.settingsState.hasPassword` 派生 |
| 首次设置 | `hasPassword=false` 时只展示新密码和确认密码，不展示短信验证码 |
| 二次修改 | `hasPassword=true` 时展示当前密码、短信验证码、新密码和确认密码 |
| 验证码 | 点击获取验证码后消费 `account.password_change_code_sent` 的 `message` 和 `challenge_id` |
| 保存接口 | 首次设置调用 `POST /api/v1/account/password`，二次修改调用 `PATCH /api/v1/account/password` |
| 数据回写 | 成功响应的 `has_password` 必须写回 `CurrentUserStore` |
| Toast | 成功展示后端 `message`，失败展示后端错误 `message` |

新增账号密码 UI E2E 时优先覆盖以下最小链路：

| 步骤 | 断言 |
|---|---|
| 验证码登录并进入账号与安全 | 登录密码状态显示 `未设置` |
| 首次设置密码 | Toast 显示 `登录密码已设置`，返回账号与安全后状态显示 `已设置` |
| 退出后密码登录 | 使用刚设置的密码登录成功，`CurrentUserStore.hasPassword=true` |
| 二次修改发送验证码 | Toast 显示 `验证码已发送` |
| 旧密码错误 | Toast 显示 `当前登录密码错误` |
| 二次修改成功 | Toast 显示 `登录密码已修改`，后续密码登录使用新密码成功 |

UI E2E 禁止从本地 mock 状态直接打开设置密码页；该页面需要 Keychain access token 生成授权头。

### 5.3 登录设备 UI E2E 接入约束

登录设备页已经接入 `SettingsDeviceSessionStore -> SettingsDeviceSessionRepository -> /api/v1/account/devices` 数据流。

| 项 | 约束 |
|---|---|
| 入口 | 登录后从 `我的 -> 设置 -> 登录设备管理` 进入 |
| 前置状态 | 至少完成一次验证码登录；移除其他设备场景需要同一账号再创建第二个设备 session |
| 列表接口 | 页面加载调用 `GET /api/v1/account/devices` |
| 详情接口 | 点击列表项使用 `session_id` 调用 `GET /api/v1/account/devices/{session_id}` |
| 移除接口 | 详情页移除按钮调用 `DELETE /api/v1/account/devices/{session_id}` |
| 当前设备 | `is_current_device=true` 的设备只允许通过退出登录移除 |
| Toast | 成功展示后端 `message=登录设备已移除`，失败展示 `message=当前设备请通过退出登录移除` |
| 数据回写 | 移除成功后从 Store 列表中删除对应 `sessionID`，详情页关闭 |

新增登录设备 UI E2E 时优先覆盖以下最小链路：

| 步骤 | 断言 |
|---|---|
| 登录并进入设备管理 | 页面存在设备列表，当前设备展示在线状态 |
| 点击当前设备 | 详情页展示设备名、平台和当前位置占位 |
| 移除当前设备 | Toast 显示 `当前设备请通过退出登录移除`，列表仍保留当前设备 |
| 创建第二设备 session | 列表出现第二台设备且 `is_current_device=false` |
| 移除第二设备 | Toast 显示 `登录设备已移除`，列表删除第二台设备 |
| 被移除设备 refresh | HTTP 层返回 `auth.refresh_invalid` |

UI E2E 点击详情必须传 `sessionID`；`deviceID` 可能在重新登录后复用，不能作为详情和移除接口路径参数。

### 5.4 Home UI E2E 接入约束

首页已经接入 `CurrentUserStore -> HomeRootScreen -> HomeDashboardStore -> HomeDashboardRepository` 数据流。

| 项 | 约束 |
|---|---|
| 入口 | 登录成功后进入 Home Tab |
| 请求上下文 | `HomeDashboardStore.load` 继续使用 `currentUserStore.userID` 派生接口上下文 |
| 普通用户昵称 | `new_user`、`pet_owner`、`family_caretaker` 的身份卡和宠物头图昵称从 `CurrentUserStore.displayName` 展示 |
| 商家名称 | `certified_merchant`、`unverified_merchant` 的工作台名称继续从 `HomeDashboardSnapshot.identity.displayName` 展示 |
| 昵称更新 | Profile 保存昵称后，回到 Home 不应断言旧 `snapshot.identity.displayName` |
| Store 注入 | `HomeRootScreen` 必须接收根部同一个 `CurrentUserStore`，禁止仅传 `currentUserID` 后在页面内复制昵称 |

新增 Home UI E2E 时优先覆盖以下最小链路：

| 步骤 | 断言 |
|---|---|
| 新用户登录进入 Home | 空态身份卡显示登录响应或 `/profile/me` 写入的当前昵称 |
| 用户有宠物时进入 Home | 宠物头图“已陪伴 <昵称>”使用 `CurrentUserStore.displayName` |
| 修改昵称后回 Home | 身份卡和宠物头图同步显示新昵称 |
| 商家账号进入 Home | 工作台名称显示商家名称，不使用个人昵称覆盖 |

### 6.1 Xcode 测试运行纪律

运行 iOS 单测和 UI Test 时使用 `-only-testing` 固定最小目标，降低 XCTest 临时设备膨胀风险。

| 场景 | 命令约束 |
|---|---|
| 当前用户数据源回归 | `-only-testing:maohuobanTests/AuthViewModelTests -only-testing:maohuobanTests/CurrentUserStoreTests -only-testing:maohuobanTests/HomeGenderSymbolTests` |
| Profile/Settings 接口接入回归 | `-only-testing:maohuobanTests/CurrentUserProfileRepositoryTests -only-testing:maohuobanTests/ProfileUserEditStoreTests -only-testing:maohuobanTests/ProfileUserEditDraftTests -only-testing:maohuobanTests/SettingsPasswordRepositoryTests -only-testing:maohuobanTests/SettingsPasswordStoreTests -only-testing:maohuobanTests/SettingsDeviceSessionRepositoryTests -only-testing:maohuobanTests/SettingsMockStoreTests -only-testing:maohuobanTests/MHBBackendEndpointTests` |
| Auth UI E2E | 只跑目标用例 `maohuobanUITests/MaohuobanAuthUITests/testAuthFlowFromPhoneCodeToPasswordRecovery` |
| Home UI E2E | 只跑目标用例 `maohuobanUITests/MaohuobanHomeUITests/testNewUserHomeShowsCreatePetEmptyState` |

`xcodebuild test` 已输出 `** TEST SUCCEEDED **` 或明确失败后，如果长时间停在 `Finalize test log` / `waiting for record to finish saving`，按以下顺序处理：

| 步骤 | 命令 |
|---|---|
| 1. 确认残留测试进程 | `ps -axo pid,ppid,stat,command \| rg 'xcodebuild test.*maohuoban'` |
| 2. 只终止已完成或失去验证价值的残留进程 | `kill <pid>` |
| 3. 检查 XCTest 临时设备膨胀 | `du -sh ~/Library/Developer/XCTestDevices 2>/dev/null` |
| 4. 大量 UI Test 后清理临时设备 | `rm -rf ~/Library/Developer/XCTestDevices/*` |

清理 XCTest 临时设备只在确认没有正在运行的 `xcodebuild test` 后执行。

## 7. 常见失败处理

| 现象 | 检查点 | 处理 |
|---|---|---|
| `Connection refused` | `lsof -nP -iTCP:18080 -sTCP:LISTEN` | 启动 E2E 后端 |
| preflight 在 legal probe 失败 | `LEGAL_PROBE_PATH`、法务迁移、后端启动参数 | 优先使用默认 `/api/v1/legal-documents/user_agreement`，确认迁移已执行 |
| HTTP E2E 清库失败 | `DATABASE` 指向 | 使用 `maohuoban_test` |
| 验证码错误 | Redis DB 或 key 前缀混用 | 使用 `REDIS_URL=redis://127.0.0.1:6379/15` 和 `REDIS_KEY_PREFIX=maohuoban:e2e:auth` |
| UI Test 误连局域网服务 | `MHB_BACKEND_BASE_URL` 和启动参数 | 使用 `MHB_BACKEND_BASE_URL=http://127.0.0.1:18080` |
| 密码登录按钮被遮挡 | 系统保存密码 Sheet | 保留 `dismissPasswordSavePromptIfPresent` 轮询逻辑 |
| 找不到退出登录入口 | Profile 入口变化 | 同步更新 `logoutFromProfile` 和设置页 accessibility id |
| Profile 字段断言失败 | 登录响应和 `/profile/me` 契约 | 对齐 `AuthUser.profile`、Profile DTO 和 mapper |
| Profile policy 断言失败 | `/profile/me` 或 `PATCH /profile/me` 响应 | 确认 `display_name_edit_policy`、`bio_edit_policy` 由后端统一计算并返回 |
| Profile 超限未触发 | `user_profile_field_changes` 记录 | 确认测试库已清理，且 PATCH 只在字段实际变化时计数 |
| 账号密码状态错误 | `CurrentUserStore.hasPassword` 写回 | 确认设置密码和修改密码成功响应使用 `data.has_password` 更新当前用户源 |
| 修改密码提示缺失验证码 | `challenge_id` 丢失 | 确认 UI 先调用 `POST /api/v1/account/password/change-code`，再提交 PATCH |
| 登录设备详情 404 | 路径参数使用了 `device_id` | 详情和删除接口统一使用后端返回的 `session_id` |
| 移除设备后列表未刷新 | Store 未按 `sessionID` 删除 | 确认 `removeDevice(sessionID:)` 成功后同步删除列表项并清空详情 |
| 当前设备被移除 | 后端当前 session 判断错误 | 确认 access token 中的 session 与目标 `session_id` 比对后返回 `account.current_device_remove_forbidden` |
| 被移除设备仍可 refresh | refresh session 未撤销 | 确认 `device_sessions.revoked_at` 已写入，被移除 refresh 返回 `auth.refresh_invalid` |
| Toast 断言失败 | 响应 `message` | 后端所有成功/失败响应返回可展示中文 `message` |

## 8. 新增 E2E 用例规范

| 规则 | 要求 |
|---|---|
| 地址 | 默认 `127.0.0.1:18080`，通过环境变量覆盖 |
| 数据库 | 默认 `maohuoban_test`，脚本清理前确认变量 |
| Toast | 所有 HTTP 响应断言非空 `message` |
| 隐私字段 | 公开或当前用户响应按契约断言敏感字段缺失 |
| 当前用户数据源 | 首页普通用户身份卡、首页宠物头图、我的页、个人主页、我的动态、动态详情、收藏夹内容页、详情评论输入栏、本地新评论和设置页身份字段从登录响应或 `/profile/me` 写入 `CurrentUserStore` 后展示 |
| Store 注入 | iOS 仅 App 根部创建 `CurrentUserStore`，下游 screen/store 必须显式注入同一实例 |
| Profile | 登录响应和 `/profile/me` 的 `maohuoban_id`、`display_name`、`avatar_presentation` 保持一致 |
| Profile media | 头像/背景上传接口必须返回完整 `CurrentProfileData`、可展示 `message` 和可解析媒资 `url` |
| Profile 编辑策略 | 新增可编辑字段限制时同步补 response policy、429 code 和 Toast message 断言 |
| Account security | 新增账号安全字段时同步补 `GET /api/v1/account/security` 响应、iOS DTO 和 Store 写回测试 |
| Password | 修改密码流程必须覆盖首次设置、重复设置、验证码、旧密码错误、成功修改 |
| Device sessions | 登录设备流程必须覆盖列表、详情、当前设备不可删、其他设备可删和 refresh 失效 |
| UI 路径 | 页面入口变化时同步更新 accessibility id 和 helper |
| 测试范围 | 使用 `-only-testing` 跑最小目标 |

新增后端接口时，先补 HTTP 契约或 E2E，再接 iOS UI E2E。
新增 UI E2E 时，通过真实登录态进入 Profile 和 Settings 页面；不要用 mock 用户资料直接打开当前用户页面。
