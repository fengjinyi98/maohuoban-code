## 1. 核心结论

个人资料体系拆成三层。

| 层 | 作用 | 公开性 |
|---|---|---|
| 认证账号 | 登录、手机号、密码状态、设备会话 | 仅当前用户和后端内部可见 |
| 个人资料 | 昵称、简介、头像、背景、性别、生日、所在地 | 当前用户可编辑，公开页按展示规则输出 |
| 平台身份 | 毛伙伴号、注册序号、冷启动资格 | 毛伙伴号公开；注册序号内部保存；创世伙伴资格后续由勋章体系消费 |

推荐关键规则：

| 规则 | 设计 |
|---|---|
| 默认昵称 | 不使用递增序号，使用 `毛伙伴用户` + 非顺序短码，例如 `毛伙伴用户7K29Q` |
| 毛伙伴号 | 后端生成不可修改、不可枚举的公开 ID |
| 注册序号 | 后端内部 `join_sequence` 单调递增，支撑创世伙伴资格和年度报告 |
| 创世伙伴资格 | 本阶段只保留资格判断，不发放徽章；后续勋章体系统一按 `join_sequence <= 5000` 回溯发放“创世伙伴” |
| 密码状态 | 以后端是否存在 `password_credentials` 记录为事实源，对前端返回 `has_password` |
| 首次设置密码 | 只校验登录态和新密码强度 |
| 修改密码 | 旧密码 + 短信验证码双验证 |
| 性别展示 | `unknown` 或关闭展示时，头像框不显示性别 |
| 昵称限制 | 2-24 字符，30 天最多修改 5 次 |
| 简介限制 | 最多 100 字，30 天最多修改 3 次 |
| 头像/背景上传 | Profile 域提供独立上传接口，成功后直接更新 `user_profiles.avatar_asset_id / cover_asset_id` 并返回完整当前资料 |

## 3. 领域边界

| 域 | 负责 | 不负责 |
|---|---|---|
| Auth | 登录、手机号身份、密码、token、设备 session、账号安全状态 | 昵称、简介、头像、生日、所在地 |
| Profile | 个人资料、毛伙伴号、注册序号、资料编辑策略、地区字典、公开主页资料 | token、refresh、密码 hash、勋章发放 |
| Badge/Growth | 创世伙伴徽章、等级、经验、勋章展示策略 | 账号认证和资料字段持久化 |

后端推荐新增 profile 分层 crate：

| crate | 职责 |
|---|---|
| `maohuoban-profile-domain` | 个人资料实体、性别、地区、编辑策略、领域错误 |
| `maohuoban-profile-application` | 读取/更新资料、默认资料创建、编辑次数策略、冷启动资格判断预留 |
| `maohuoban-profile-infrastructure` | PostgreSQL 持久化、毛伙伴号生成、地区字典读取 |
| `maohuoban-profile-http` | `/api/v1/profile/**`、`/api/v1/account/security`、设备管理 DTO |

Auth 与 Profile 的协作边界：

| 场景 | 协作方式 |
|---|---|
| 手机验证码首次登录 | Auth 创建用户后调用 Profile 端口初始化 `user_profiles` |
| 登录响应 | Auth 返回账号安全摘要和资料摘要，避免首屏二次请求阻塞 |
| 个人资料编辑 | Profile 接收 Auth 验证后的 `user_id` |
| 设备管理 | 设备 session 属于 Auth，HTTP 可放在 account/security 路由下 |

## 5. 默认身份生成规则

### 5.1 注册序号

`join_sequence` 只表达用户加入平台的内部顺序。

| 项 | 规则 |
|---|---|
| 生成时机 | 首次手机号验证码登录创建 `users` 时 |
| 生成方式 | PostgreSQL sequence |
| 是否可修改 | 不可修改 |
| 是否公开 | 默认不公开 |
| 主要用途 | 创世伙伴资格、年度报告、运营分析、稀有身份授予 |

不把递增序号放入公开毛伙伴号或默认昵称，避免外部推断平台用户规模。

### 5.2 默认昵称

默认昵称使用非顺序短码。

| 项 | 规则 |
|---|---|
| 格式 | `毛伙伴用户` + 5 位非顺序短码 |
| 示例 | `毛伙伴用户7K29Q` |
| 来源 | 从毛伙伴号或随机源派生，排除易混字符 |
| 是否唯一 | 不强制唯一，唯一身份由毛伙伴号承担 |
| 修改后 | 用户自定义昵称覆盖默认昵称 |

短码字符集建议使用 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`，避开 `0/O/1/I`。

### 5.3 毛伙伴号

毛伙伴号是公开身份编码，不承载真实注册顺序。

| 项 | 规则 |
|---|---|
| 生成方 | 后端 |
| 是否可修改 | 不可修改 |
| 是否公开 | 公开 |
| 可枚举性 | 应降低可枚举性 |
| 推荐形态 | 10-12 位数字或字母数字 ID，带校验位更佳 |

推荐生成策略：

```text
body = random_numeric_or_base32(length = 10~12)
check_digit = luhn_or_mod97(body)
maohuoban_id = body + check_digit
insert with unique index
on conflict retry
```

毛伙伴号点击提示文案：

```text
毛伙伴号是毛伙伴为账号生成的平台内唯一身份编码，当前版本暂不支持修改。
```

## 6. 创世伙伴资格

### 6.1 本阶段边界

本阶段不落地完整勋章体系。

| 项 | 规则 |
|---|---|
| 当前要做 | 保存 `users.join_sequence`，确保未来可以回溯判断早期用户资格 |
| 当前不做 | 不新增 `user_badges`，不在登录响应和 profile 响应返回真实 badges，不实现勋章展示开关 |
| 后续统一落地 | 等等级、经验、勋章页、勋章展示开关和发放任务一起实现 |
| 前端现状 | mock 中已有 `genesis_partner / 创世伙伴 / 限量 5,000 人` |

### 6.2 阈值候选

创世伙伴徽章后续建议对齐前端 mock，采用前 5000 名用户。

| 阈值 | 判断 |
|---|---|
| 前 1000 | 稀缺感强，覆盖面偏窄 |
| 前 5000 | 推荐，和当前前端“创世伙伴”限量文案一致，稀缺感更强 |
| 前 10000 | 覆盖更广，但会削弱“创世”稀缺感 |

### 6.3 后续发放规则

| 项 | 规则 |
|---|---|
| badge code | `genesis_partner` |
| 展示名 | `创世伙伴` |
| 发放条件 | `users.join_sequence <= 5000` |
| 发放时机 | 勋章体系落地后通过回溯任务补发 |
| 展示控制 | 后续由勋章页统一实现 |
| 公开内容 | 只展示勋章，不展示具体 `join_sequence` |

年度报告可以在登录态私有页面展示：

```text
你是第 3287 位加入毛伙伴的用户。
```

公开主页只展示：

```text
创世伙伴
```

## 7. 个人资料字段规则

### 7.1 字段清单

| 字段 | 可编辑 | 展示规则 |
|---|---|---|
| 昵称 | 可编辑 | 个人主页、我的页、头像 alt、动态作者 |
| 毛伙伴号 | 不可编辑 | 编辑页展示，点击说明 |
| 性别 | 可编辑 | 按展示开关决定是否进入头像框 |
| 性别展示开关 | 可编辑 | 关闭后所有公开场景隐藏性别 |
| 所在地 | 可编辑 | 展示省/市/区归一化文案 |
| 生日 | 可编辑 | 当前用户可见；公开展示后续可加开关 |
| 个人简介 | 可编辑 | 个人主页资料区 |
| 头像 | 可编辑 | 用户头像媒资，上传成功后全局当前用户头像刷新 |
| 背景 | 可编辑 | 个人主页背景媒资，上传成功后个人主页背景刷新 |

### 7.2 昵称规则

| 项 | 规则 |
|---|---|
| 长度 | trim 后 2-24 字符 |
| 空白 | 首尾空白 trim，内部空白保留 |
| 禁止字符 | 控制字符、`@`、`<`、`>`、`/` |
| 修改次数 | 30 天最多 5 次 |
| 重复昵称 | 允许重复 |
| 错误码 | `profile.display_name_invalid`、`profile.display_name_edit_limit_exceeded` |

修改策略响应：

```json
{
  "max_count": 5,
  "used_count": 1,
  "remaining_count": 4,
  "window_days": 30,
  "window_ends_at": "2026-07-23T03:54:00Z",
  "display_text": "7月23日前还可以修改 4 次昵称。"
}
```

### 7.3 个人简介规则

| 项 | 规则 |
|---|---|
| 长度 | trim 后最多 100 字 |
| 是否可空 | 可清空 |
| 修改次数 | 30 天最多 3 次 |
| 错误码 | `profile.bio_invalid`、`profile.bio_edit_limit_exceeded` |

简介为空时前端展示 `未添加`。

### 7.4 生日规则

| 项 | 规则 |
|---|---|
| 格式 | `yyyy-MM-dd` |
| 数据库类型 | `date` |
| 最晚日期 | 今天 |
| 最早日期 | 1900-01-01 |
| 可空 | 可空 |
| 展示 | 已设置展示 `yyyy-MM-dd`，未设置展示 `未添加` |
| 错误码 | `profile.birthday_invalid` |

后端响应可同时返回：

| 字段 | 示例 |
|---|---|
| `birthday` | `1999-12-31` |
| `birthday_display_text` | `1999-12-31` |

### 7.5 所在地规则

所在地必须来自后端地区字典。

| 字段 | 示例 |
|---|---|
| `country_name` | `中国` |
| `province_name` | `浙江省` |
| `city_name` | `温州市` |
| `district_name` | `鹿城区` |
| `display_text` | `浙江省 鹿城区` |

直辖市去重展示：

| 选择 | 展示 |
|---|---|
| 北京市 / 北京市 / 朝阳区 | `北京市 朝阳区` |
| 上海市 / 上海市 / 浦东新区 | `上海市 浦东新区` |

错误码：

| code | 场景 |
|---|---|
| `profile.region_invalid` | code/name 不匹配或不在字典中 |
| `profile.region_unavailable` | 地区字典暂不可用 |

### 7.6 性别和头像框展示

后端原始字段：

| 字段 | 值 |
|---|---|
| `gender` | `male/female/unknown` |
| `is_gender_visible` | `true/false` |

头像展示输出：

| `gender` | `is_gender_visible` | `avatar_presentation.sex` | `avatar_presentation.sex_visibility` |
|---|---:|---|---|
| `male` | `true` | `male` | `visible` |
| `female` | `true` | `female` | `visible` |
| `unknown` | `true` | `unknown` | `hidden` |
| `male` | `false` | `unknown` | `hidden` |
| `female` | `false` | `unknown` | `hidden` |
| `unknown` | `false` | `unknown` | `hidden` |

前端头像框统一消费 `avatar_presentation`，避免各业务页面重复判断。

### 7.7 用户头像和主页背景上传规则

用户头像和主页背景属于 Profile 域资料字段，上传成功后直接替换当前资料引用。

| 项 | 头像 | 主页背景 |
|---|---|---|
| 接口 | `POST /api/v1/profile/me/avatar` | `POST /api/v1/profile/me/cover` |
| 表单 | multipart `file`，可选 `source_client` | multipart `file`，可选 `source_client` |
| 支持格式 | JPEG / PNG / WebP | JPEG / PNG / WebP |
| 大小限制 | 建议 5 MB | 建议 10 MB |
| 尺寸策略 | 前端可裁剪为方形，后端保存真实宽高 | 前端按主页背景比例裁剪，后端保存真实宽高 |
| 媒资用途 | `media_assets.usage_kind=user.avatar` | `media_assets.usage_kind=user.cover.image` |
| 当前引用 | `user_profiles.avatar_asset_id` | `user_profiles.cover_asset_id` |
| Toast message | `头像已保存` | `主页背景已保存` |

后端实现边界：

| 层 | 职责 |
|---|---|
| HTTP | 解析 multipart，校验登录态，映射标准响应和错误 message |
| Application | 编排上传、校验用途、替换当前资料引用、返回最新 `CurrentProfileData` |
| Infrastructure | 写入 `media_assets`、计算 sha256/宽高、写入对象存储、更新 `user_profiles` |
| Media Content | 继续通过 `/api/v1/media/assets/{asset_id}/content` 输出内容 |

替换头像或背景时，旧资产不再作为当前资料引用。后续有清理任务时可以把旧资产标记为 `cleanup_pending`，并写入 `media_cleanup_jobs`。

不复用宠物 `media_bindings` 表绑定用户头像或背景；该表以 `pet_id` 为强约束，用户资料只更新 `user_profiles` 的当前资产字段。

前端实现边界：

| 层 | 职责 |
|---|---|
| Preview Screen | 只负责选择、裁剪、预览和触发保存 |
| `CurrentUserProfileRepository` | 通过 `MHBHTTPClient.postMultipart` 调用 Profile 上传接口 |
| `ProfileUserEditStore` | 管理上传中/失败状态，成功后消费后端 `message` |
| `CurrentUserStore` | 用响应里的 `avatar` / `cover` 刷新全局当前用户展示 |
| 展示组件 | 优先使用远端 `url`，为空时回退本地默认头像或默认背景 |

本地预览只作为即时反馈；接口成功后的后端响应是最终事实源。

密码状态规则：

| 事实源 | 响应 |
|---|---|
| `password_credentials` 存在 | `has_password=true`、`password_status_text=已设置` |
| `password_credentials` 不存在 | `has_password=false`、`password_status_text=未设置` |

### 9.2 首次设置密码

`POST /api/v1/account/password`

请求：

```json
{
  "new_password": "Abc12345",
  "confirm_password": "Abc12345"
}
```

规则：

| 项 | 规则 |
|---|---|
| 认证 | 必须登录 |
| 适用状态 | `has_password=false` |
| 验证码 | 不需要 |
| 旧密码 | 不需要 |
| 新密码强度 | 8-20 位，至少两种字符类型 |
| session | 保持当前设备登录 |

错误码：

| code | 场景 |
|---|---|
| `account.password_already_set` | 已有密码时调用首次设置 |
| `account.password_weak` | 新密码强度不足 |
| `account.password_mismatch` | 两次密码不一致 |

### 9.3 修改密码验证码

`POST /api/v1/account/password/change-code`

规则：

| 项 | 规则 |
|---|---|
| 认证 | 必须登录 |
| 发送目标 | 当前绑定手机号 |
| purpose | `password_change` |
| 冷却 | 复用验证码冷却策略 |

### 9.4 修改密码

`PATCH /api/v1/account/password`

请求：

```json
{
  "current_password": "Old12345",
  "challenge_id": "challenge-id",
  "code": "123456",
  "new_password": "New12345",
  "confirm_password": "New12345"
}
```

规则：

| 项 | 规则 |
|---|---|
| 认证 | 必须登录 |
| 适用状态 | `has_password=true` |
| 校验 | 旧密码 + 短信验证码双验证 |
| session | 推荐撤销其他设备，保留当前设备 |
| 审计事件 | `account.password_changed` |

错误码：

| code | 场景 |
|---|---|
| `account.password_not_set` | 未设置密码时调用修改 |
| `account.current_password_invalid` | 旧密码错误 |
| `auth.invalid_code` | 验证码错误 |
| `auth.code_expired` | 验证码过期 |
| `account.password_weak` | 新密码强度不足 |

### 9.5 忘记密码重置

现有账号恢复接口保留。

| 接口 | 处理 |
|---|---|
| `POST /api/v1/account-recovery/code` | 给指定手机号发恢复验证码 |
| `POST /api/v1/account-recovery/reset-password` | 验证码 + 新密码，撤销旧 session |

忘记密码属于未登录恢复流程；修改密码属于已登录安全设置流程。
