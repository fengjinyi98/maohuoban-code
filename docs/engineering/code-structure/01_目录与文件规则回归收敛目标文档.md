```text

  -> 按模块拆分文件（纯结构迁移，不改逻辑）
  -> 逐切片真实构建/测试验证
```

## 10. 不变约束

| 约束 | 说明 |
|---|---|
| 只做结构拆分 | 不借机重写业务流程、视觉、导航或 API 语义 |
| 不改变代码逻辑 | 所有拆分必须保持等价迁移，不修改条件分支、算法、状态机或错误处理 |
| 不改变 UI 行为 | 拆分后页面外观、交互、动画、手势保持完全一致 |
| 不引入 Bug 回归 | 已修复的裁剪 Bug（`intersection` 逻辑）、导航修复、Rust 警告修复必须保持有效 |
| View 纯渲染 | SwiftUI `body`、同步 formatter、selector、resolver 仍保持无副作用 |
| 系统导航 | 不引入自绘导航替代系统 `NavigationStack` / 系统返回手势 |
| UIKit 边界 | 不为普通 SwiftUI 拆分新增 UIKit 桥接 |
| 访问控制 | 拆出的 helper 默认 `private` / `fileprivate` / internal 最小暴露 |
| 测试有效 | 拆分后的测试仍验证原行为，不把断言降级为存在性检查 |
| 无新增警告 | 拆分后 `xcodebuild` 和 `cargo clippy` 不得引入新增警告 |
| 临时日志 | 若拆分过程中需要临时日志定位，遵循 `debug-with-temp-logs` skill 纪律，验证后清理 |
| 主工作区隔离 | 所有代码修改只在 `.worktree/file-rules-convergence` 分支内进行，主工作区不产生拆分相关改动 |
| worktree 独立基线 | worktree 从当前 `main` 新开，不继承主工作区未提交改动；拆分完成后合并回 `main` |

## 11. 风险

| 风险 | 处理 |
|---|---|
| 大文件拆分引入访问级别扩散 | 每次只开放编译必需的最小符号，优先同目录 internal 或 private helper |
| SwiftUI 子 View 拆出后状态传递膨胀 | 只传子 View 实际读取数据，命令通过显式闭包转发 |
| Rust 模块拆分破坏可见性 | 先建立 `mod` 结构，再逐个移动函数和类型，保持 public API 不变 |
| Rust 根 src 迁移影响路由聚合 | 迁移后验证 `lib.rs` 的路由注册顺序和中间件链不变 |
| 裁剪 Bug 修复被意外覆盖 | 拆分前确认 `MHBRectImageCropScreen+Actions.swift` 不在拆分范围，验收门禁增加手动裁剪验证 |
| 构建耗时导致反馈慢 | 按 Feature / crate 切片验证，最终再跑完整门禁 |
| 拆分引入隐式行为变化 | 每个切片前先固化测试基线，切片后立即对比测试结果 |
| 当前工作区有未提交改动 | 在 `.worktree/file-rules-convergence` 独立分支实施，主工作区只保留文档；worktree 不继承未提交改动 |
