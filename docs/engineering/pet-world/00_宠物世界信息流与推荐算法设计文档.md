# 宠物世界信息流与推荐算法设计文档

- 文档版本：v0.1
- 更新时间：2026-06-17
- 适用范围：iOS 宠物世界 Tab、Rust 推荐服务、宠物事件、公开内容流、宠物关系推荐
- 关联产品文档：`docs/product/strategy/01_主页与底部Tab产品方向.md`、`docs/product/prd/00_V1_PRD_产品总纲与核心流程.md`
- 关联约束：`AGENTS.md`

## 1. 当前结论

宠物世界定位为：

> **以宠物为主体的宠物事件流。**

宠物世界承接完整 UGC，但内容组织单位是宠物事件、宠物经验和宠物轻关系。推荐流不能退化成人类达人流，也不能变成只展示相似宠物的窄关系流。

V1 推荐采用“宠物相关性打底 + 优质内容探索混入”的混合流：

| 内容池 | 作用 | 冷启动建议占比 |
|---|---|---|
| 轻关系相关 | 使用档案字段建立同品种、同年龄阶段等弱关系 | 40% |
| 优质内容 | 高质量、高互动、审核精选的宠物事件 | 30% |
| 成长 / 经验 | 饮食、护理、训练、医疗、用品等沉淀内容 | 20% |
| 探索内容 | 其他品种、猫狗交叉、不同生活方式 | 10% |

## 2. 产品边界

| 模块 | 负责内容 | 边界 |
|---|---|---|
| 宠物世界 | 宠物事件、宠物经验、宠物轻关系推荐 | 不做传统社区 / 小组，不做同城服务入口 |
| 同城 Tab | 医院、商家、服务、交易、线下履约 | 承接本地实体和交易信任边界 |
| 首页 | 当前宠物工作台、今日照护、最近时间线 | 不承载完整推荐流 |

位置可以作为推荐特征，例如“附近相似阶段”“同医院复诊”，但不作为宠物世界一级频道。宠物世界里的地理信息只用于推荐解释、筛选和实体页跳转。

## 3. 页面信息结构

V1 页面保持轻量，首屏只回答三个问题：

| 问题 | UI 表达 |
|---|---|
| 正在为哪只宠物推荐 | 顶部显示“为 糯米 推荐” |
| 当前看什么类型内容 | 顶部频道：推荐 / 关注 / 成长 / 经验 |
| 为什么出现这些内容 | 卡片上的低干扰短标签 |

```text
┌─────────────────────────┐
│ 宠物世界          [发布] │
│ 为 糯米 推荐             │
├─────────────────────────┤
│ [推荐] [关注] [成长] [经验] │
├─────────────────────────┤
│ 推荐提示 Chips            │
│ [布偶猫] [幼猫] [优质经验] [新鲜内容] │
├─────────────────────────┤
│ Feed Card                │
│ Feed Card                │
│ Feed Card                │
└─────────────────────────┘
```

频道职责：

| 频道 | 内容 |
|---|---|
| 推荐 | 轻关系、优质内容、成长经验和探索内容混合 |
| 关注 | 已关注宠物的公开事件 |
| 成长 | 到家、生日、训练、体重、阶段变化等宠物成长记录 |
| 经验 | 饮食、护理、医疗、用品、出行等可沉淀内容 |

“关系”不做一级频道。冷启动阶段关系粒度弱，作为频道容易产生空态和误导；关系应作为推荐解释和轻筛选出现。

## 4. Feed 卡片设计

卡片主视觉服务内容，推荐关系只做轻提示。

```text
┌─────────────────────────┐
│ 头像  奶盖        关注   │
│      布偶猫 · 8个月       │
├─────────────────────────┤
│                         │
│        图片 / 视频        │
│                         │
├─────────────────────────┤
│ 最近开始换粮，记录一下...  │
│ #幼猫成长 #换粮           │
├─────────────────────────┤
│ ♥ 128  💬 24  ☆   同龄   │
└─────────────────────────┘
```

卡片层级：

| 层级 | 展示内容 | 设计要求 |
|---|---|---|
| 宠物身份 | 宠物头像、宠物名、品种、年龄阶段 | 强于用户账号 |
| 内容主体 | 图片 / 视频、正文、话题 | 占据卡片主视觉 |
| 互动 | 点赞、评论、收藏、关注宠物 | 行为对象优先是宠物和事件 |
| 推荐解释 | 一个 2-4 字短标签 | 默认低干扰，点击后再展开解释 |

推荐解释不常驻展示完整句子。详细解释进入底部弹层、详情页或长按说明。

```text
短标签：同龄
展开解释：因为糯米也是幼猫阶段，系统推荐了相近成长记录。
```

## 5. 冷启动关系策略

V1 只能使用添加宠物时已经获取到的档案字段建立轻关系。

| 关系 | 数据来源 | 示例解释 |
|---|---|---|
| 同品种 | 宠物类型、品种 | 同为布偶猫 |
| 同年龄阶段 | 出生日期、到家时间 | 都处于幼猫阶段 |
| 同性别 | 性别 | 同为母猫 |
| 同绝育状态 | 绝育状态 | 同为未绝育阶段 |
| 相近体重 | 体重 | 体型接近 |
| 相似性格 | 性格标签 | 都偏胆小、怕生 |

后续数据沉淀后逐步增强：

| 阶段 | 新增关系 | 依赖数据 |
|---|---|---|
| 内容互动后 | 同话题、同事件类型、相似互动偏好 | 发布内容、点赞、收藏、评论 |
| 健康记录后 | 同健康问题、同护理阶段 | 健康事件、体重、疫苗、驱虫 |
| 实体链路后 | 同医院、同医生、同来源、同窝 | 医疗、交易、商家、窝次关系 |

## 6. 推荐算法目标

推荐算法目标不是单纯提高点击率，而是在三个目标之间平衡：

| 目标 | 说明 |
|---|---|
| 宠物相关性 | 让用户感知“这是为我的宠物推荐的” |
| 内容质量 | 保证信息流有发现感和可读性 |
| 多样性 | 避免满屏都是同品种、同阶段或同一类内容 |

最终排序建议采用可解释的加权模型起步，后续再替换为学习排序。

```text
final_score =
    relation_score * 0.40
  + quality_score  * 0.30
  + experience_score * 0.15
  + freshness_score * 0.10
  + exploration_score * 0.05
  - fatigue_penalty
  - safety_penalty
```

冷启动阶段权重建议：

| 分数 | 权重 | 说明 |
|---|---:|---|
| `relation_score` | 0.40 | 基于档案字段的轻关系 |
| `quality_score` | 0.30 | 内容质量、互动质量、审核精选 |
| `experience_score` | 0.15 | 是否属于可沉淀经验 |
| `freshness_score` | 0.10 | 发布时间和近期热度 |
| `exploration_score` | 0.05 | 跨品种、跨猫狗、不同生活方式探索 |

数据变多后，`relation_score` 可以降低到 0.30，`exploration_score` 提升到 0.10-0.15，避免推荐流过窄。

## 7. 召回与排序流程

```text
PetWorldFeedRequest
  -> 当前宠物上下文
  -> 召回候选内容池
  -> 权限和安全过滤
  -> 单卡打分
  -> 混排和去重
  -> 生成短推荐标签
  -> 返回 Feed Snapshot
```

### 7.1 当前宠物上下文

| 字段 | 用途 |
|---|---|
| `pet_id` | 当前推荐主体 |
| `species` | 同类型、跨类型探索 |
| `breed` | 同品种轻关系 |
| `birth_date` | 年龄阶段 |
| `sex` | 轻关系 |
| `neuter_status` | 成长阶段相关性 |
| `weight` | 体型相近 |
| `personality_tags` | 性格相似 |
| `city` | 只作为推荐特征，不作为频道 |

### 7.2 候选内容池

| 内容池 | 召回条件 |
|---|---|
| 轻关系池 | 同品种、同年龄阶段、同标签 |
| 质量池 | 最近高收藏、高评论、高完播、人工精选 |
| 经验池 | 带经验类话题或被收藏率高的长尾内容 |
| 探索池 | 与当前宠物不同品种、不同类型但质量高的内容 |
| 关注池 | 用户已关注宠物的公开内容 |

### 7.3 权限过滤

进入宠物世界的内容必须满足：

| 规则 | 要求 |
|---|---|
| 可见范围 | 仅公开内容进入推荐流 |
| 敏感内容 | 医疗、交易、位置敏感内容默认不进入公开流，除非用户明确公开 |
| 删除状态 | 已删除、待清理、申诉中内容不展示 |
| 安全审核 | 违规、低质、重复搬运内容过滤 |

## 8. 单卡打分细则

### 8.1 关系分

```text
relation_score =
    species_match       * 0.20
  + breed_match         * 0.25
  + age_stage_match     * 0.25
  + personality_match   * 0.15
  + life_state_match    * 0.10
  + location_hint       * 0.05
```

说明：

| 项 | 取值 |
|---|---|
| `species_match` | 猫 / 狗 / 其他是否一致 |
| `breed_match` | 品种是否一致或相近 |
| `age_stage_match` | 幼年、成年、老年等阶段 |
| `personality_match` | 性格标签交集 |
| `life_state_match` | 绝育、到家阶段、体重区间 |
| `location_hint` | 城市或服务实体相关，仅作为轻权重 |

### 8.2 内容质量分

```text
quality_score =
    media_quality       * 0.20
  + completion_signal   * 0.20
  + save_rate           * 0.25
  + comment_quality     * 0.15
  + author_trust        * 0.10
  + manual_pick         * 0.10
```

早期没有足够行为数据时，人工精选和内容基础质量权重可以更高。

### 8.3 经验分

经验分用于区分“可沉淀经验”和普通日常。

| 特征 | 示例 |
|---|---|
| 结构化话题 | `#换粮`、`#绝育恢复`、`#幼猫到家` |
| 收藏率 | 收藏率高于同类内容 |
| 长尾价值 | 发布时间较早但仍持续被搜索 / 收藏 |
| 内容完整度 | 有过程、结果、注意事项 |

### 8.4 探索分

探索分用于保证内容流不局限于当前宠物相似关系。

| 规则 | 目标 |
|---|---|
| 异品种高质量内容加权 | 让用户看到其他品种的优质内容 |
| 猫狗交叉少量混入 | 保持世界感 |
| 新鲜内容少量混入 | 避免信息流只展示成熟热门内容 |
| 低频话题保护 | 给长尾经验内容曝光 |

## 9. 混排和多样性规则

仅靠 `final_score` 排序容易导致信息流单调，必须增加混排约束。

| 约束 | 建议 |
|---|---|
| 同品种连续限制 | 连续 3 张同品种后插入优质或探索内容 |
| 同宠物曝光限制 | 同一宠物每 20 张最多出现 2 次 |
| 同内容类型限制 | 图片、视频、文本经验混排 |
| 同推荐标签限制 | 连续相同短标签不超过 2 张 |
| 新鲜内容保底 | 每 20 张至少 2 张新鲜内容 |
| 探索内容保底 | 每 20 张至少 2 张探索内容 |

混排后示例：

```text
1. 同品种同年龄：布偶猫幼猫换粮记录
2. 优质经验：柯基洗护避坑
3. 成长记录：英短到家第 7 天
4. 探索内容：萨摩耶第一次坐车
5. 同年龄：幼猫绝育前准备
```

## 10. 推荐解释生成

卡片默认只展示一个短标签：

| 短标签 | 详细解释 |
|---|---|
| 同龄 | 因为糯米也处于幼猫阶段 |
| 同品种 | 因为这只宠物也是布偶猫 |
| 成长 | 这是一条相近阶段的成长记录 |
| 经验 | 很多宠物家长收藏了这条经验 |
| 优质 | 这条内容近期互动质量较高 |
| 新鲜 | 这是近期发布的新内容 |

解释优先级：

```text
强关系 > 轻关系 > 经验价值 > 内容质量 > 探索新鲜
```

当一条内容同时满足多个条件时，只展示最能体现宠物主体感的一个短标签。完整解释留给详情页或弹层。

## 14. 空态和冷启动体验

| 场景 | 展示 |
|---|---|
| 用户无宠物 | 引导创建宠物，同时展示精选宠物世界示例 |
| 用户有宠物但内容少 | 使用优质内容和探索内容补足 |
| 关系数据不足 | 不展示“关系”频道，只展示短标签 |
| 关注为空 | 推荐关注相似宠物或返回推荐流 |

空态示例：

## 16. 验收标准

| 类型 | 标准 |
|---|---|
| 产品主体 | 卡片主身份是宠物，不是人类账号 |
| 内容多样性 | 推荐流不是满屏同品种 / 同年龄内容 |
| 关系轻量 | 卡片默认只显示一个短标签 |
| 同城边界 | 宠物世界不出现同城一级频道 |
| 冷启动 | 只依赖宠物档案字段也能生成可解释推荐 |
| 隐私 | 仅公开事件进入推荐流 |
| 可测试 | 推荐解释、打分、混排、重排均为可单测纯规则 |
