# 首页沉浸式头图融合实验

## 1. 实验目标

首页沉浸式头图需要复刻 Apple Music 详情页的层次关系：头图主体保持清晰，图片底部自然融入页面背景，头图滚出可视区域后背景稳定为从头图提取出的纯色，并根据滚动深度增强内容可读性。

本实验先验证图层模型和色值提取策略，再进入具体 SwiftUI 实现。

## 2. 当前视觉判断

参考 Apple Music 真机滚动观察和截图，头图下方背景在头图滚出后表现为稳定纯色，而不是模糊图片背景。图片和背景交界处存在向上的雾化过渡，视觉上不是单纯线性透明淡出。

当前判断：

| 视觉现象 | 推测机制 |
|---|---|
| 头图滚出后背景稳定 | 使用头图提取色作为页面背景 |
| 图片底部边界不硬 | 清晰头图底部使用羽化 alpha mask |
| 人物下半身被背景吞入 | 叠加同色雾化 overlay 压低图片底部对比度 |
| 内容始终可读 | 随滚动进度叠加可读性 scrim |

## 3. 草稿图层模型

推荐实验模型命名为：纯色背景承接 + 图片羽化消失 + 同色雾化压边。

```text
最上层：业务内容、按钮、卡片、标题
可读层：随滚动增强的半透明 scrim
雾化层：从透明到提取色的同色渐变 overlay
头图层：清晰图片，底部使用羽化 alpha mask
背景层：从头图底部区域提取的纯色背景
```

各层职责：

| 图层 | 职责 | 关键参数 |
|---|---|---|
| 背景层 | 承接头图之外的页面背景 | 提取色、滚动透明度 |
| 头图层 | 展示清晰宠物图片 | 高度、填充方式、下拉缩放 |
| 头图 alpha mask | 控制头图底部逐渐消失 | fade 起点、fade 高度、曲线 |
| 同色雾化 overlay | 降低头图底部细节和边界感 | 提取色、起点、结束点、最大透明度 |
| 可读性 scrim | 保障按钮和正文可读 | 滚动进度、深浅模式、透明度上限 |

## 4. PS 场景对应

如果在 PS 中制作该效果，操作会是：

1. 使用吸管或区域平均，从头图底部过渡区域取样得到背景色。
2. 新建纯色填充图层，作为整个页面背景。
3. 将清晰头图放在纯色背景上方。
4. 给清晰头图添加图层蒙版，使用黑白渐变让底部逐渐隐藏。
5. 对蒙版边缘做 feather 或高斯模糊，让透明变化向上扩散。
6. 在头图底部上方叠加同色渐变层，从透明渐变到背景色，用于压低图片底部对比度。
7. 在内容区域叠加低透明度 scrim，随内容密度和滚动状态增强可读性。

## 5. 当前色值提取逻辑

当前项目保留的基础工具位于：

`maohuoban/maohuoban/Infrastructure/ImageProcessing/MHBImageAverageColorExtractor.swift`

当前公开入口：

```swift
static func extractVerticalColors(
    from image: UIImage,
    count: Int,
    maxDimension: CGFloat = 200
) -> [UIColor]
```

当前流程：

| 步骤 | 行为 |
|---|---|
| 1 | 入参 `count <= 0` 时返回空数组 |
| 2 | 如果图片最长边超过 `maxDimension`，按比例缩小到最长边 200pt |
| 3 | 将图片转换为 `CIImage` |
| 4 | 按 `count` 把图片纵向切成多个水平条带 |
| 5 | 对每个条带使用 Core Image `areaAverage()` 计算平均色 |
| 6 | 使用 `CIContext.render` 输出 1x1 RGBA 像素 |
| 7 | 将 RGBA 字节转换为 `UIColor` 数组 |

当前条带顺序：

| index | 取样区域 |
|---|---|
| 0 | 图片顶部第一个水平条带 |
| count - 1 | 图片底部最后一个水平条带 |

因为代码使用：

```swift
y: extent.height - CGFloat(index + 1) * tileHeight
```

所以 `index = 0` 对应 Core Image 坐标中的最高条带，也就是视觉图片顶部。

## 6. 当前逻辑的适配性

当前工具适合做纵向氛围渐变，因为它可以得到从上到下的多段平均色。

当前工具还不够适合 Apple Music 这类头图融合实验，原因是实验需要重点匹配图片底部交界区域，而不是整张图的纵向颜色序列。

当前缺口：

| 缺口 | 影响 |
|---|---|
| 没有直接提取底部过渡区域主色 | 背景色可能被图片顶部或主体颜色干扰 |
| 没有排除透明 / 极亮 / 极暗异常像素 | 背景色可能偏灰、偏白或偏黑 |
| 没有输出单一背景承接色 | UI 层还需要自行选择哪一段颜色 |
| 没有输出雾化 overlay 推荐色 | 交界处 overlay 可能和背景色不一致 |

## 7. 下一步待讨论

下一轮重点讨论色值提取策略：

| 议题 | 草稿方向 |
|---|---|
| 背景承接色取哪里 | 优先取头图底部 20%-35% 区域 |
| 是否继续保留纵向多段色 | 保留，用于后续渐变氛围能力 |
| 首页融合需要什么新接口 | 增加提取底部承接色的独立接口 |
| 是否需要色值修正 | 需要限制亮度和饱和度，避免背景影响文字可读性 |
| 是否需要缓存 | 图片资源稳定时应缓存，避免滚动或渲染路径重复计算 |
