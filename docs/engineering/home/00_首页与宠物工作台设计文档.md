- 文档版本：v0.1
- 更新时间：2026-06-14
- 适用范围：iOS 首页前端、Rust 首页聚合服务、宠物档案、宠物事件、商家多宠工作台、提醒、关系推荐
- 关联设计稿：`docs/html/maohuoban-homepage-design.html`

- 关联约束：`AGENTS.md`

## 1. 首页定调

首页定调为：

> **以宠物为主体的信任工作台。**

首页每天回答三个问题：

| 问题 | 用户感知 | 系统能力 |
|---|---|---|
| 这只宠物是谁 | 当前毛孩子是首屏主角 | 当前宠物档案、身份栏、宠物切换 |
| 今天状态如何 | 用户能快速知道照护和提醒 | 今日照护、提醒、待办 |
| 哪些记录正在形成可信档案 | 用户能看到时间线持续增长 | 宠物事件账本、最近时间线、商家证据快照 |

首页定位高于传统 UGC 推荐流和单纯工具集合。首页负责聚合摘要、模块入口和优先级编排；深层业务规则分别归属宠物档案、事件记录、提醒、商家工作台、宠物世界、同城和消息模块。

## 2. 首页边界

| 能力 | 首页职责 | 归属模块 |
|---|---|---|
| 当前宠物 | 展示当前宠物主卡和切换入口 | 宠物档案 |
| 今日照护 | 展示食欲、精神、排泄、体重等摘要 | 宠物事件 / 健康记录 |
| 提醒 | 展示最近待处理提醒和入口 | 提醒模块 |
| 快捷动作 | 根据上下文进入记录、医院、导入交易 | 发布记录 / 同城 / 交易 |
| 今日伙伴 | 展示一条高质量宠物关系摘要 | 宠物世界 / 关系推荐 |
| 最近时间线 | 展示最近 2-3 条关键事件 | 宠物事件账本 |
| 商家看板 | 展示多宠状态、窝次入口、待补记录 | 商家工作台 |
| 新用户空态 | 引导创建宠物或导入交易宠物 | 宠物档案 / 交易 |

首页禁止承担以下职责：

| 禁止项 | 原因 |
|---|---|
| 在首页实现宠物事件业务规则 | 事件规则需要服务普通用户、商家、交易、医疗和保险 |
| 在首页实现推荐算法 | 推荐策略属于宠物世界或关系推荐服务 |
| 在首页实现窝次和血缘规则 | 关系树属于宠物关系 / 商家域 |
| 在 SwiftUI 渲染路径触发写状态副作用 | 违反 `AGENTS.md` SwiftUI 渲染副作用约束 |

## 3. 用户身份与首页形态

| 身份 | 首页形态 | 首屏重点 |
|---|---|---|
| 新用户无宠物 | 创建宠物引导 + 高质量示例内容 | 创建第一只毛孩子 |
| 普通养宠用户 | 当前宠物主体页 | 宠物主卡、今日照护、快捷记录、最近时间线 |
| 多宠家庭 | 当前宠物主体页 + 宠物切换 | 多宠切换、当前宠物提醒 |
| 认证猫舍 / 犬舍 | 机构宠物工作台 | 多宠状态、窝次、父母关系、健康记录完整度 |
| 认证宠物店 | 机构宠物工作台 | 店内宠物、寄养 / 洗护 / 交易状态、待办 |
| 商家未认证 | 认证引导态 | 认证价值、材料、审核进度 |

## 4. 核心读模型

首页使用聚合读模型 `HomeDashboardSnapshot`。后端负责根据当前账号、当前身份、当前宠物或机构上下文生成快照；前端只按 section 渲染。

```text
HomeDashboardSnapshot
  -> identity
  -> selected_pet
  -> pet_switcher
  -> care_summary
  -> reminders
  -> quick_actions
  -> partner_recommendation
  -> recent_timeline
  -> merchant_dashboard
  -> empty_state
```

| 字段 | 说明 |
|---|---|
| `identity` | 当前首页身份：普通用户、共管成员、认证商家、未认证商家 |
| `selected_pet` | 当前宠物主卡摘要，普通用户首页核心 |
| `pet_switcher` | 多宠切换数据，商家模式可显示宠物组或窝次 |
| `care_summary` | 今日照护指标摘要 |
| `reminders` | 待处理提醒摘要 |
| `quick_actions` | 当前上下文可用动作 |
| `partner_recommendation` | 今日伙伴关系卡摘要 |
| `recent_timeline` | 最近关键事件 |
| `merchant_dashboard` | 商家多宠工作台摘要，普通用户为空 |
| `empty_state` | 新用户、未认证商家、已认证无宠物等空态 |

## 5. 宠物事件底座

普通用户记录和商家记录共用 `PetEvent` 事件底座。

| 类型 | 子类型示例 | 核心字段 | 默认可见范围 |
|---|---|---|---|
| 日常 | 吃饭、玩耍、出门、情绪 | 文本、图片 / 视频、地点、心情 | 公开或仅自己 |
| 成长 | 到家、换牙、生日、第一次洗澡 | 时间、里程碑、附件 | 公开 |
| 健康 | 疫苗、驱虫、体重、异常观察 | 指标、时间、提醒、附件 | 仅自己 / 共管成员 |
| 医院 | 就诊、复诊、检查报告、处置记录 | 医院、医生、检查、诊断、附件 | 仅自己 / 授权可见 |
| 交易 | 看宠、体检、合同、交付 | 卖家、买家、合同、体检、付款 | 双方 / 授权可见 |
| 商家 | 出生、窝次、父母、在售、预定、交付 | 窝次、父母、健康承诺、证据快照 | 买家可见或授权可见 |
| 纪念 | 重要瞬间、长期回忆、告别 | 文本、图片 / 视频、时间 | 自定义 |

事件原则：

| 原则 | 说明 |
|---|---|
| 必须绑定主体 | 每条事件绑定宠物、商家宠物组或窝次 |
| 追加型记录 | 关键商家事件保留证据快照，后续修改形成新版本或审计记录 |
| 可见范围默认收紧 | 医疗、交易、商家承诺默认不公开 |
| 买家可见时间线 | 商家可为在售宠物生成买家可见时间线 |
| 可回流实体页 | 公开或授权事件可回流宠物世界、同城商家、医院实体页 |

## 6. 商家记录与窝次追溯

商家记录目标是让猫舍、犬舍、宠物店从开始使用毛伙伴的时刻起，持续沉淀可追溯记录。

| 概念 | 说明 |
|---|---|
| `MerchantProfile` | 认证商家主体，包含认证状态、城市、类型 |
| `ManagedPet` | 商家管理的宠物，可以在售、预定、已售、留种、停售 |
| `Litter` | 一窝宠物，关联父母、出生日期、出生数量、成活数量 |
| `PetRelationship` | 父母、同窝、同来源、转让、共管等关系 |
| `EvidenceSnapshot` | 商家事件发布时的证据快照，包含附件、字段、发布时间和发布者 |

当前实现状态：

| 能力 | 实现口径 |
|---|---|
| 商家主体 | `MerchantProfile` 作为认证商家主体，首页优先识别当前用户名下 verified 商家 |
| 窝次摘要 | `Litter` 读取父母宠物、出生日期、出生数量、成活数量和可售幼宠数 |
| 关系追溯 | `PetRelationship` 读取父母、同窝等关系边，作为商家关系树应用用例输入 |
| 商家首页 | `MerchantDashboardSummary` 应用读模型聚合状态统计、窝次、关系边和最近事件，再映射到首页快照 |

商家首页展示的是机构宠物工作台：

| 模块 | 内容 | 交互 |
|---|---|---|
| 机构身份栏 | 店名 / 舍名、城市、认证状态、提醒 | 进入认证资料、待办 |
| 多宠状态看板 | 在售、预定、已售、待体检、待补记录 | 筛选宠物组 |
| 窝次 / 血缘入口 | 父母、出生批次、同窝关系 | 进入窝次详情 |
| 待办列表 | 待回复咨询、待补健康记录、待更新照片 | 快速处理 |
| 店内宠物动态 | 最近健康、成长、交易事件 | 编辑或发布事件 |
| 经营快捷动作 | 新增宠物、记录健康、发布可售状态 | 进入对应流程 |

## 7. ID 策略

当前阶段统一使用 UUID。

| 对象 | ID 类型 | 说明 |
|---|---|---|
| 用户 | UUID v4 | 沿用认证系统 |
| 宠物 | UUID v4 | PostgreSQL `uuid`，API 使用字符串 |
| 宠物事件 | UUID v4 | 追加型事件，后续可按时间索引排序 |
| 商家 | UUID v4 | 认证实体 ID |
| 窝次 | UUID v4 | 关系树和批次追溯 |
| 附件 / 证据快照 | UUID v4 | 关联对象存储与审计 |

选择 UUID 的原因：

| 维度 | 决策 |
|---|---|
| 当前依赖 | Rust workspace 已引入 `uuid`，认证系统已使用 UUID |
| 数据库兼容 | PostgreSQL 原生 `uuid` 类型成熟 |
| API 契约 | 前后端均以字符串传输，跨平台简单 |
| 后续演进 | 如需要时间有序 ID，可单独评审 UUIDv7 或 ULID，不影响外部字符串契约 |

## 8. 后端分层

后端继续采用 Rust workspace 分层。

| Crate | 层级 | 职责 |
|---|---|---|
| `maohuoban-pet-domain` | Domain | 宠物档案、事件、窝次、关系、商家宠物状态 |
| `maohuoban-pet-application` | Application | 宠物事件记录、时间线查询、商家多宠用例、端口 traits |
| `maohuoban-pet-infrastructure` | Infrastructure | PostgreSQL repository、附件引用、查询优化 |
| `maohuoban-pet-http` | Interface | 宠物档案、事件、商家宠物 HTTP DTO 和路由 |
| `maohuoban-home-domain` | Domain | 首页聚合读模型和值对象 |
| `maohuoban-home-application` | Application | 首页快照查询用例、section 编排策略 |
| `maohuoban-home-http` | Interface | `/api/v1/home/dashboard` 路由和 DTO |
| `maohuoban_rust` | Composition | 装配 auth、legal、pet、home 路由和依赖 |

依赖方向：

```text
home-http -> home-application -> home-domain
home-application -> pet-application port
pet-http -> pet-application -> pet-domain
pet-infrastructure -> pet-application / pet-domain
maohuoban_rust 装配所有实现
```

## 9. iOS 前端分层

iOS 首页遵循 Feature 目录分层和 SwiftUI MVVM。

| 目录 | 职责 |
|---|---|
| `Features/Home/Domain` | 首页读模型、section 类型、action 类型 |
| `Features/Home/Data` | DTO、Repository、API Client 适配 |
| `Features/Home/Stores` | `@MainActor @Observable` Store，异步加载和状态派生 |
| `Features/Home/Presentation` | `HomeRootScreen` 和各 section View |
| `Features/Home/Presentation/Sections` | 宠物主卡、今日照护、提醒、快捷动作、伙伴、时间线、商家看板 |
| `Features/Pet/Domain` | 宠物写入草稿、响应摘要、物种 / 性别 / 事件类型 / 可见范围 |
| `Features/Pet/Data` | 宠物写入 Repository，适配 `/api/v1/pets` 和 `/api/v1/pets/{pet_id}/events` |
| `Features/Pet/Stores` | `@MainActor @Observable PetWriteStore`，承接创建宠物和记录事件状态流 |
| `Features/Pet/Presentation` | 创建宠物、日常记录、健康记录页面和表单组件 |
| `Features/Merchant/Domain` | 商家在管宠物列表读模型、经营状态、来源类型 |
| `Features/Merchant/Data` | 商家读取 Repository，适配 `/api/v1/merchants/{merchant_id}/pets` 和 `/api/v1/merchants/{merchant_id}/litters/{litter_id}` |
| `Features/Merchant/Stores` | `@MainActor @Observable MerchantPetsStore` / `MerchantLitterDetailStore`，承接商家宠物列表和窝次详情加载状态流 |
| `Features/Merchant/Presentation` | 商家宠物状态筛选列表、窝次详情和空态 / 失败态页面 |

SwiftUI 规则：

| 规则 | 首页落地方式 |
|---|---|
| View 只负责渲染和转发事件 | 网络加载、状态写入放 Store |
| 多 section 拆独立 View | 每个首页模块一个 `View` 类型 |
| 子视图只收自己读取的数据 | Section 使用窄输入 |
| 渲染路径无副作用 | `body`、同步 helper 不写 UserDefaults、缓存、网络 |
| 文案可本地化 | 非 View 类型用户可见文案使用 `LocalizedStringResource` |
| 视觉 token | 颜色、字体、间距、圆角来自 `MaohuobanDesignSystem` |

首页动作写入边界：

| 首页路由 | 当前落地 | 归属 |
|---|---|---|
| `.createPet` | 进入 `PetCreateScreen`，提交 `POST /api/v1/pets`，成功后刷新首页快照 | `Features/Pet` |
| `.recordDaily(petID)` | 进入 `PetEventRecordScreen(mode: .daily)`，提交 `event_kind = daily` | `Features/Pet` |
| `.recordHealth(petID)` | 进入 `PetEventRecordScreen(mode: .health)`，提交 `event_kind = health` | `Features/Pet` |
| `.merchantPets(merchantID, status)` | 进入 `MerchantPetsScreen`，读取指定状态下的商家在管宠物 | `Features/Merchant` |
| `.addMerchantPet(merchantID)` | 进入 `MerchantPetCreateScreen`，提交 `POST /api/v1/merchants/{merchant_id}/pets`，成功后刷新首页快照 | `Features/Merchant` |
| `.merchantLitter(merchantID, litterID)` | 进入 `MerchantLitterDetailScreen`，读取窝次基础信息、父母、同窝幼宠、关系边和近期事件 | `Features/Merchant` |
| `.timelineEvent(eventID)` | 进入 `PetEventDetailScreen`，读取当前用户可访问的单条事件账本详情 | `Features/Pet` |
| 医院、交易、商家任务等路由 | 当前保留系统导航占位页，等待对应业务模块接管 | 对应 Feature |

写入请求继续通过 `x-maohuoban-user-id` 传递当前用户上下文。iOS 端只传递后端返回的宠物和事件 ID，不自行生成业务 ID。

## 10. 接口契约

首页第一阶段接口：

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/v1/home/dashboard` | `GET` | 返回当前登录用户首页聚合快照 |
| `/api/v1/merchants/{merchant_id}/pets?status={status}` | `GET` | 返回认证商家指定经营状态下的在管宠物 |
| `/api/v1/merchants/{merchant_id}/pets` | `POST` | 为认证商家新增一只在管宠物，默认来源为 `merchant_managed` |
| `/api/v1/merchants/{merchant_id}/litters/{litter_id}` | `GET` | 返回认证商家窝次详情，包含父母、同窝幼宠、关系边和近期事件 |
| `/api/v1/pet-events/{event_id}` | `GET` | 返回当前用户可访问的单条宠物事件详情 |

当前阶段首页通过 `x-maohuoban-user-id` 请求头传递登录用户上下文；后续接入正式鉴权中间件后，由后端从 access token 解析当前用户。

成功响应：

```json
{
  "success": true,
  "code": "home.dashboard_loaded",
  "message": "首页已加载",
  "data": {
    "identity": {
      "kind": "pet_owner",
      "display_name": "毛伙伴用户"
    },
    "selected_pet": {
      "id": "b4e47d94-9b31-4e91-9c20-51052d342d7b",
      "name": "糯米",
      "species": "dog",
      "breed": "比熊犬",
      "age_text": "2岁",
      "status_text": "今天精神很好"
    },
    "recent_timeline": []
  }
}
```

失败响应沿用统一 API response：

```json
{
  "success": false,
  "code": "auth.unauthorized",
  "message": "登录状态已失效",
  "data": null
}
```

## 12. 分阶段实施

| Phase | 范围 | 验收 |
|---|---|---|
| 1 | 工程文档、后端首页契约、iOS 首页骨架 | 文档提交；`GET /api/v1/home/dashboard` 返回稳定快照；首页能渲染设计稿核心模块 |
| 2 | 宠物档案与事件账本 | 可创建宠物、记录事件、展示时间线 |
| 3 | 提醒与健康摘要 | 今日照护和提醒由真实事件派生 |
| 4 | 商家多宠工作台 | 支持商家多宠状态、窝次入口、窝次详情、待补记录 |
| 5 | 关系推荐与 UGC 空态 | 今日伙伴和新用户 UGC 补空态接入可配置推荐 |
| 6 | 联调、性能、观测 | 前后端 E2E、诊断事件、质量门禁通过 |
