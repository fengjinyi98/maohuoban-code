# 宠物相册回忆式拼贴幻灯片后续方案

## 结论

回忆式拼贴幻灯片属于产品完成后的增强功能。当前阶段先完成相册基础管理、照片增删、详情浏览和后端数据链路；幻灯片播放作为后续锦上添花项目单独立项。

## 功能定位

该功能不是普通单图轮播，而是多张照片以不规则拼贴方式进入、停留、替换和消失的回忆播放体验。目标是让宠物相册具备“自动整理成回忆片段”的情绪价值，而不是承担基础浏览职责。

## 核心难点

| 难点 | 说明 |
|---|---|
| 随机可观赏性 | 需要随机感，但布局、节奏、动画必须受控，避免画面杂乱、遮挡和频繁闪烁。 |
| 网络资源流畅性 | 相册图片来自后端，不能按本地相册假设一次性读取大量原图。 |
| 大相册规模 | 用户可能拥有几千张照片，客户端必须分页读取播放清单，只保留小窗口资源。 |
| 动画复杂度 | 多图同时入场、出场、保留和替换，需要 scene diff 与动画编排。 |
| 主体裁切 | 宠物主体需要尽量留在画面安全区域，后续可能需要焦点数据或主体识别。 |

## 推荐架构

| 模块 | 核心职责 |
|---|---|
| `PetAlbumSlideshowPlanner` | 基于随机种子、照片元数据和模板库生成播放 scene。 |
| `PetAlbumSlideshowTemplate` | 定义 1-4 张图的安全拼贴 slot，使用归一化坐标表达布局。 |
| `PetAlbumSlideshowScorer` | 为多个候选 scene 打分，选择可观赏性更高的一幕。 |
| `PetAlbumSlideshowPlayerStore` | 管理播放、暂停、scene 预取、网络分页和缓存窗口。 |
| `PetAlbumSlideshowView` | 渲染当前 scene 与下一 scene，执行入场、出场和替换动画。 |

## 受控随机策略

| 随机对象 | 允许范围 | 约束 |
|---|---|---|
| 每幕照片数 | 1-4 张 | 连续多幕平均密度保持稳定。 |
| 模板选择 | 从模板库随机 | 同模板避免连续重复。 |
| 替换比例 | 替换 1 张、2 张或全部替换 | 保留与全替换交替出现。 |
| 入场动画 | 淡入、轻滑入、轻缩放、轻旋入 | 旋转角度控制在小范围。 |
| 停留时间 | 2.4-4.2 秒 | 照片越多停留越久。 |
| Ken Burns | 轻微缩放和平移 | 缩放幅度控制在舒适区间。 |

## 网络与缓存策略

| 场景 | 策略 |
|---|---|
| 播放清单 | 后端按相册、排序版本和 cursor 分页返回。 |
| 播放图片 | 使用 screen-size 派生图，原图只用于查看和下载。 |
| 预取窗口 | 以 scene 为单位预取当前、下一幕和再下一幕图片。 |
| 内存缓存 | 只保留当前 2-3 幕已解码图片。 |
| 磁盘缓存 | 按 `albumID + mediaID + derivativeKind + etag` 做 LRU 缓存。 |
| 网络失败 | 当前幕继续播放，下一幕缺图时跳过候选或短暂缓冲。 |

## 分期建议

| 版本 | 范围 |
|---|---|
| v1 | 6-8 个固定模板、受控随机、screen 图预取、轻量 scene diff 动画。 |
| v2 | 宠物主体焦点、智能高光排序、按时间和事件聚类。 |
| v3 | 音乐节拍、导出视频、分享回忆片段。 |

## 暂缓原因

该功能需要独立的播放引擎、模板体系、缓存策略和大量视觉调参。当前产品阶段优先交付相册基础闭环，包括创建、浏览、添加照片、删除照片、删除相册、权限和后端同步。回忆式拼贴幻灯片在基础链路稳定后再单独进入设计和实现。
