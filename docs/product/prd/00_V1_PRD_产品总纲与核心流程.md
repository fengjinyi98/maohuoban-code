## 1. 产品定位

毛伙伴是一个以宠物为主体的长期协同平台。

产品围绕每只宠物的主页、时间线、伙伴关系、同城服务、医疗记录、交易履约与保险协同展开。人负责记录、管理、决策和履约；宠物承载内容、关系、记录、医疗、交易和保险闭环。

毛伙伴这个名字的产品含义是：

> 让每只毛孩子拥有自己的主页、时间线和伙伴关系。

V1 目标是建立一套最小完整产品骨架，让用户打开 App 后立刻感知到“当前主角是我的毛孩子”，并能通过宠物事件、宠物关系和同城实体形成持续使用理由。

## 2. V1 产品目标

| 目标 | 说明 | 验收标准 |
|---|---|---|
| 建立宠物主体心智 | 首页围绕当前宠物展开 | 首屏最大视觉中心是当前宠物 |
| 建立宠物事件体系 | 发布语义从发帖转为记录宠物事件 | 每条内容必须归属到一只宠物或一个商家宠物组 |
| 建立宠物关系推荐 | 推荐依据围绕宠物画像和关系标签 | 首页出现“今日伙伴”，宠物世界支持关系解释 |
| 建立同城信任边界 | 医院、猫舍、犬舍、宠物店、交易、服务在同城中聚合 | 同城实体有基础资料页和咨询入口 |
| 承接多身份用户 | 普通养宠用户和认证商家共用一个 C 端 App | 首页根据身份呈现宠物主卡或多宠工作台 |
| 为 HIS 和保险预留主链路 | 日常记录、就医摘要、交易证据能进入宠物档案 | V1 数据模型保留医疗、交易、授权字段 |

## 3. 产品原则

| 原则 | 产品含义 | 对设计的要求 |
|---|---|---|
| 宠物是主体 | 内容、推荐、时间线、关系都围绕宠物展开 | 页面标题、卡片、发布流程优先展示宠物 |
| 人是管理者 | 主人、家庭成员、商家、医生参与记录和决策 | 权限体系必须区分记录权、管理权、授权权 |
| 事件是内容单位 | 日常、健康、医院、交易、纪念都归入宠物事件 | UGC 流展示事件卡，事件绑定宠物档案 |
| 关系制造惊喜 | 同窝、同城、同病种、同医院、同来源触发联动 | 推荐卡必须解释“为什么相关” |
| 同城承接信任 | 本地实体降低交易、医疗和服务履约成本 | 同城页聚合实体、服务、交易和预约 |
| MCP 先于薄 MVP | 主链路、角色关系、商业闭环先完整 | V1 功能可轻，但对象模型和路径要完整 |

## 4. 用户角色

| 角色 | 核心诉求 | 高频任务 | 首页形态 |
|---|---|---|---|
| 普通养宠用户 | 记录宠物状态、获得经验、找到靠谱服务 | 记录日常、查看提醒、浏览伙伴、咨询同城服务 | 当前宠物主体页 |
| 家庭 / 情侣共同养宠 | 多人共同维护同一只宠物 | 共管记录、提醒同步、就医信息共享 | 共享宠物主体页 |
| 猫舍 / 犬舍 | 管理多只宠物、血缘、批次、健康和出售状态 | 更新多宠状态、回复咨询、维护父母血缘 | 多宠工作台 |
| 宠物店 | 管理店内宠物、洗护寄养和服务咨询 | 服务咨询、订单沟通、店内宠物记录 | 店铺宠物工作台 |
| 合作医院 / 医生 | 获取就医前摘要、沉淀可信接诊记录 | 查看摘要、回流检查和复诊记录 | V1 以实体页和预约协作为主 |
| 保险合作方 | 获取授权后的连续记录和理赔材料 | 查看授权材料、核验时间线 | V1 预留授权和材料结构 |
| 平台运营 | 管理内容、实体、认证和风险 | 审核商家、处理举报、维护话题 | 后台能力另行拆分 |

## 5. 核心对象模型

| 对象 | 定义 | 关键字段 | 关联关系 |
|---|---|---|---|
| 宠物档案 `PetProfile` | 每只宠物的一生主档案 | 名字、物种、品种、生日、性别、绝育状态、来源、城市、头像、健康概览 | 事件、关系、成员、交易、医疗、保险 |
| 宠物事件 `PetEvent` | 宠物发生过的一次可记录事件 | 类型、时间、正文、图片 / 视频、地点、状态指标、可见范围 | 宠物档案、话题、关系标签、实体 |
| 宠物关系 `PetRelationship` | 两只或多只宠物之间的结构化关系 | 关系类型、置信来源、触发时间、展示文案 | 同窝、同城、同病种、同医院、同来源 |
| 话题 `Topic` | 内容聚合和搜索结构 | 名称、别名、分类、热度、风险等级 | 事件、搜索、运营推荐 |
| 同城实体 `LocalEntity` | 医院、猫舍、犬舍、宠物店等本地节点 | 类型、城市、地址、认证状态、服务、评分、联系入口 | 宠物、事件、交易、预约、会话 |
| 用户身份 `UserIdentity` | 一个账号在当前场景下的身份 | 普通用户、共管成员、商家、医院成员、运营 | 权限、首页形态、消息会话 |
| 宠物成员 `PetMember` | 人与宠物的管理关系 | 角色、权限、加入方式、是否可授权 | 宠物档案、用户身份 |
| 消息会话 `Conversation` | 人、商家、医院、系统之间的沟通容器 | 会话类型、参与方、关联宠物、关联订单、未读数 | 消息、交易、咨询、评论 |
| 交易记录 `TradeRecord` | 交易履约和证据链 | 卖家、买家、宠物、合同、体检、付款、交付状态 | 宠物档案、商家实体、医院实体 |
| 授权记录 `ConsentRecord` | 医疗、保险、共管等数据访问授权 | 授权方、被授权方、范围、期限、撤回状态 | 医院、保险、家庭成员 |

## 6. 信息架构

底部 Tab 定档为 5 个：

| 顺序 | Tab | 产品职责 | 核心入口 |
|---|---|---|---|
| 1 | 首页 | 当前宠物主体页 / 宠物工作台 | 当前宠物、今日照护、快捷记录、今日伙伴、最近时间线 |
| 2 | 宠物世界 | 基于宠物画像推荐宠物事件、宠物关系和宠物经验 | 推荐流、关注流、话题、关系筛选 |
| 3 | 同城 | 本地医院、猫舍、犬舍、宠物店、交易与服务 | 实体列表、地图、预约、咨询、透明套餐 |
| 4 | 消息 | 私信、评论、交易沟通、商家咨询、系统通知 | 会话列表、未读、待回复、系统提醒 |
| 5 | 我的 | 主人账号、身份认证、订单、授权、设置 | 账号资料、身份切换、认证、订单、隐私 |

发布入口采用全局 `+` 或首页快捷动作，语义是：

> 为当前宠物记录一次事件。

## 7. 首页 PRD

### 7.1 首页目标

首页负责建立宠物主体感和高频回访理由。

| 首页目标 | 对应模块 |
|---|---|
| 让用户看到当前毛孩子 | 当前毛孩子主卡 |
| 让用户知道今天要处理什么 | 今日照护 |
| 让用户快速记录事件 | 快捷动作 |
| 让用户产生宠物关系惊喜 | 今日伙伴 |
| 让用户看到一生档案正在连续形成 | 最近时间线 |
| 让商家管理多只宠物 | 多宠工作台 |

### 7.2 普通用户首页模块

| 顺序 | 模块 | 内容 | 交互 |
|---|---|---|---|
| 1 | 顶部身份栏 | `毛伙伴`、城市、身份状态、提醒入口 | 城市切换、提醒列表、身份切换 |
| 2 | 当前毛孩子主卡 | 宠物大图、名字、年龄阶段、今日状态、简短近况 | 进入宠物档案、编辑状态 |
| 3 | 毛孩子切换器 | 多宠横滑、添加宠物 | 切换当前宠物、创建宠物档案 |
| 4 | 今日照护 | 食欲、精神、排泄、体重、疫苗、驱虫、复诊提醒 | 快速打点、进入健康记录 |
| 5 | 快捷动作 | 记录日常、健康记录、预约医院、导入交易宠物 | 进入发布 / 预约 / 导入流程 |
| 6 | 今日伙伴 | 同窝、同城、同病种、同医院、同来源关系卡 | 查看对方宠物、评论、关注 |
| 7 | 最近时间线 | 当前宠物最近 2-3 条关键事件 | 查看完整时间线、补充记录 |

### 7.3 认证商家首页模块

| 顺序 | 模块 | 内容 | 交互 |
|---|---|---|---|
| 1 | 机构身份栏 | 店名 / 舍名、城市、认证状态、待处理提醒 | 进入认证资料、查看待办 |
| 2 | 多宠状态看板 | 在售、预定、已售、待体检、待补记录数量 | 筛选宠物组 |
| 3 | 批次 / 血缘入口 | 父母血缘、出生批次、同窝关系 | 进入批次详情 |
| 4 | 待办列表 | 待回复咨询、待补健康记录、待更新照片 | 快速处理 |
| 5 | 店内宠物动态 | 最近健康、成长、交易事件 | 编辑或发布事件 |
| 6 | 经营快捷动作 | 新增宠物、记录健康、回复咨询、发布可售状态 | 进入对应流程 |

### 7.4 首页空状态

| 场景 | 展示内容 | 主操作 |
|---|---|---|
| 新用户无宠物 | 品牌名、宠物主体说明、创建宠物入口 | 创建第一只毛孩子 |
| 有交易待导入 | 待导入宠物卡、来源说明、证据状态 | 导入为宠物档案 |
| 商家未认证 | 认证价值、所需材料、审核周期 | 提交认证 |
| 商家已认证但无宠物 | 多宠工作台说明、批量录入入口 | 新增店内宠物 |

## 8. 发布与记录事件 PRD

### 8.1 发布入口

发布入口出现位置：

| 位置 | 入口形态 | 默认上下文 |
|---|---|---|
| 首页 | 快捷动作 / 全局 `+` | 当前宠物 |
| 宠物档案 | 记录按钮 | 当前宠物 |
| 宠物世界 | 全局 `+` | 最近使用宠物 |
| 同城实体页 | 记录 / 评价 / 咨询后记录 | 当前实体 + 当前宠物 |
| 商家工作台 | 新增事件 | 当前宠物组或选中宠物 |

### 8.2 事件类型

| 类型 | 子类型示例 | 核心字段 | 默认可见范围 |
|---|---|---|---|
| 日常 | 吃饭、玩耍、出门、情绪 | 文本、图片 / 视频、地点、心情 | 公开或仅自己 |
| 成长 | 到家、换牙、生日、第一次洗澡 | 时间、里程碑、附件 | 公开 |
| 健康 | 疫苗、驱虫、体重、异常观察 | 指标、时间、提醒、附件 | 仅自己 / 共管成员 |
| 医院 | 就诊、复诊、检查报告、处置记录 | 医院、医生、检查、诊断、附件 | 仅自己 / 授权可见 |
| 交易 | 看宠、体检、合同、交付 | 卖家、买家、合同、体检、付款 | 双方 / 授权可见 |
| 纪念 | 重要瞬间、长期回忆、告别 | 文本、图片 / 视频、时间 | 自定义 |

### 8.3 发布流程

```text
进入发布入口
  -> 确认宠物
  -> 选择事件类型
  -> 填写内容和附件
  -> 选择可见范围
  -> 系统建议话题和关系标签
  -> 用户确认发布
  -> 事件进入宠物时间线
  -> 按权限进入宠物世界 / 同城实体 / 消息通知
```

### 8.4 自动补全规则

| 补全内容 | 依据 | 用户控制 |
|---|---|---|
| `#话题` | 事件类型、正文关键词、实体、病症、品种 | 可删除、可新增 |
| 关系标签 | 同窝、同城、同病种、同医院、同来源 | 可隐藏、可关闭推荐 |
| 实体绑定 | 医院、猫舍、犬舍、宠物店 | 可解绑或改选 |
| 健康字段 | 疫苗、驱虫、体重、症状 | 可编辑 |
| 时间线位置 | 事件时间 | 可修改 |

### 8.5 发布校验

| 校验项 | 规则 |
|---|---|
| 宠物归属 | 每条事件必须绑定宠物或商家宠物组 |
| 隐私 | 医疗、交易、保险相关事件默认收紧可见范围 |
| 附件 | 图片 / 视频需进入安全审核 |
| 医疗表述 | 涉及诊断建议时需要风险提示和平台审核策略 |
| 商家事件 | 可售、血缘、健康承诺等内容需保留证据快照 |

## 9. 宠物档案与时间线 PRD

### 9.1 宠物档案结构

| 分区 | 内容 | V1 要求 |
|---|---|---|
| 基础信息 | 名字、头像、物种、品种、生日、性别、绝育、城市 | 必做 |
| 成员管理 | 主人、共管成员、商家来源、授权记录 | 必做 |
| 健康概览 | 疫苗、驱虫、体重、过敏、慢病、最近异常 | 必做 |
| 时间线 | 日常、成长、健康、医院、交易、纪念事件 | 必做 |
| 伙伴关系 | 同窝、同城、同病种、同医院、同来源 | 必做基础能力 |
| 交易来源 | 来源商家、交易记录、初始状态证据 | V1 支持导入结构 |
| 医疗记录 | 就诊摘要、报告附件、复诊提醒 | V1 支持手动记录 |
| 保险协同 | 授权、保单、理赔材料 | V1 预留数据结构 |

### 9.2 时间线展示规则

| 规则 | 说明 |
|---|---|
| 以事件时间排序 | 支持补录过去事件 |
| 关键事件可置顶 | 到家、确诊、手术、交易交付、生日等可标记为关键事件 |
| 医疗和交易分层展示 | 默认摘要展示，敏感附件需授权查看 |
| 公开事件可进入宠物世界 | 仅公开内容进入推荐流 |
| 实体相关事件可回流实体页 | 医院、商家、宠物店相关事件可进入实体动态或评价体系 |

## 10. 宠物世界 PRD

### 10.1 定位

宠物世界承接完整 UGC，但内容组织单位是宠物事件、宠物关系和宠物经验。

推荐系统围绕宠物画像展开：

| 推荐维度 | 示例 |
|---|---|
| 性格 | 胆小、外向、黏人、怕生 |
| 年龄阶段 | 幼猫到家、换牙期、绝育期、老年期 |
| 位置 | 同城、附近医院、附近服务 |
| 健康问题 | 猫瘟、细小、肠胃敏感、皮肤病 |
| 来源关系 | 同猫舍、同犬舍、同窝、同父母血缘 |
| 医院关系 | 同医院就诊、同医生复诊 |
| 内容偏好 | 用户常互动的宠物事件类型 |

### 10.2 信息流卡片

| 元素 | 说明 |
|---|---|
| 宠物头像 / 名字 | 卡片主身份 |
| 宠物标签 | 年龄、品种、城市、状态 |
| 事件内容 | 文本、图片、视频、时间 |
| 关系解释 | 例如“同城同龄”“同窝伙伴”“同医院复诊” |
| 互动 | 点赞、评论、关注宠物、收藏、分享 |
| 话题 | 用于聚合和搜索 |

### 10.3 内容聚合

V1 使用三种结构承接聚合：

| 结构 | 作用 |
|---|---|
| `#话题` | 承接经验、搜索、热点和长期内容沉淀 |
| 宠物关系标签 | 承接同窝、同城、同年龄、同病种、同医院推荐 |
| 实体页 | 承接医院、猫舍、犬舍、宠物店等本地可信节点 |

V1 暂缓传统社区 / 小组，降低创建、审核、冷启动和运营成本。

## 11. 同城 PRD

### 11.1 定位

同城是毛伙伴的本地信任边界，承接医院、猫舍、犬舍、宠物店、交易、服务和线下履约。

### 11.2 同城首页模块

| 模块 | 内容 | 目的 |
|---|---|---|
| 城市定位 | 当前城市、切换城市 | 建立本地边界 |
| 搜索 | 医院、商家、服务、品种、病症 | 提升找服务效率 |
| 推荐实体 | 附近医院、认证猫舍 / 犬舍、宠物店 | 建立服务入口 |
| 透明套餐 | 体检、疫苗、驱虫、复诊等标准套餐 | 降低价格不透明 |
| 本地宠物 | 同城同阶段、同品种、同问题宠物 | 承接宠物关系 |
| 交易入口 | 同城看宠、交易 SOP、导入档案 | 承接交易闭环 |

### 11.3 实体页

| 实体 | 核心内容 | V1 操作 |
|---|---|---|
| 医院 | 资质、地址、营业时间、服务、医生、套餐、评价 | 咨询、预约、查看透明套餐 |
| 猫舍 / 犬舍 | 认证、地址范围、在售宠物、父母血缘、健康记录、售后承诺 | 咨询、看宠、关注、查看同窝 |
| 宠物店 | 服务、洗护、寄养、商品、店内宠物、评价 | 咨询、预约、查看服务 |
| 本地服务 | 上门喂养、训练、寄养等 | 咨询、预约 |

### 11.4 交易 SOP 入口

V1 需要在同城中保留交易主链路入口：

```text
浏览同城商家 / 宠物
  -> 发起咨询
  -> 线下看宠 / 预约体检
  -> 记录核验和检测结果
  -> 形成交易证据
  -> 交易完成后导入宠物档案
```

## 17. 关键流程

### 17.1 新用户创建第一只宠物

```text
打开 App
  -> 选择城市
  -> 创建宠物档案
  -> 填写基础信息
  -> 选择照护提醒
  -> 进入首页
  -> 首页展示当前宠物主卡和今日照护
```

### 17.2 用户记录一次健康异常

```text
点击记录
  -> 选择当前宠物
  -> 选择健康事件
  -> 填写症状、时间、照片 / 视频
  -> 选择可见范围
  -> 系统建议 #肠胃敏感 等话题和同病种关系
  -> 发布到宠物时间线
  -> 首页今日照护更新
  -> 必要时提示附近医院
```

### 17.3 用户发现同窝伙伴

```text
首页出现今日伙伴
  -> 展示同窝关系解释
  -> 用户进入对方宠物主页
  -> 查看公开事件
  -> 评论或关注
  -> 双方消息 / 评论通知触发
  -> 关系互动进入宠物世界推荐反馈
```

### 17.4 用户通过同城找医院

```text
进入同城
  -> 搜索或查看推荐医院
  -> 进入医院实体页
  -> 查看透明套餐和评价
  -> 发起咨询 / 预约
  -> 选择关联宠物
  -> 生成就医前摘要
  -> 就诊后记录医疗事件
```

### 17.5 商家维护多只宠物

```text
商家打开首页
  -> 进入多宠工作台
  -> 查看待补健康记录 / 待回复咨询
  -> 选择宠物或批次
  -> 发布健康 / 成长 / 可售状态事件
  -> 事件进入对应宠物档案和商家实体页
  -> 用户咨询触发消息会话
```

## 19. 风险与边界

| 风险 | 表现 | V1 应对 |
|---|---|---|
| 产品主体跑回人类社区 | 内容流强调达人、账号和普通帖子 | 卡片、发布、推荐解释全部绑定宠物 |
| 首页承载过重 | 首屏信息过多，用户找不到主操作 | 首页只保留当前宠物、今日照护、今日伙伴、最近时间线 |
| 商家需求挤压普通用户体验 | 商家工作台复杂度影响普通首页 | 根据身份切换首页形态，共用底层宠物对象 |
| 隐私风险 | 医疗、交易、位置数据被过度公开 | 敏感事件默认收紧可见范围 |
| 内容冷启动 | 宠物世界早期内容不足 | 首页关系卡、同城实体、话题聚合共同补足 |
| 同城实体质量不稳定 | 医院和商家质量差异影响信任 | 认证、评价、举报、透明套餐分阶段完善 |
| HIS / 保险落地周期长 | 外部合作推进慢 | V1 先沉淀结构化记录、授权和材料基础 |
