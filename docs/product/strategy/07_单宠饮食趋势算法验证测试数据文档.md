## 1. 核心判断

本算法的价值不在于让用户输入精确克重，而是把用户低心智记录的模糊喂食事实，逐步转换为宠物个体自己的饮食基准。

```text
用户选择 少一点 / 正常 / 多一点
-> 系统用初始权重形成相对 score
-> 储物柜规格提供总克重锚点
-> 完整物品消耗周期生成一次周期基准
-> 多个健康周期交叉验证基准变化
-> 多个分布差异足够的周期逐步学习用户真实份量权重
-> 异常、就医、体重、HIS 数据作为解释和筛选上下文
```

当前实验不是为了证明算法已经等同真实用户内测，而是验证：在模拟真实行为的数据库输入下，系统是否能产生稳定、可解释、可继续优化的个体化饮食分析结果。

## 2. 完整算法形态

### 2.1 输入数据

| 输入 | 来源 | 用途 |
|---|---|---|
| 喂食记录 | `pet_events.event_subkind = feeding` | 记录宠物、时间、食品、模糊份量 |
| 食品规格 | `food_inventory_items.spec` / `package_weight_grams` | 提供单件总克重锚点 |
| 库存状态/消耗事件 | 储物柜状态与后续消耗记录 | 判断是否形成完整物品消耗周期 |
| 异常记录 | abnormal 事件 | 判断周期是否可进入健康基准 |
| 就医/用药/病历 | HIS 回流或医疗事件 | 标记医疗期，不污染健康基准 |
| 宠物身份 | pet profile | 单宠归属、年龄解释、HIS 资料关联 |

首轮确定性数据只依赖用户能稳定提供的两类信息：

```text
模糊喂食记录 + 储物柜物品规格
```

天气、年龄、品种等因素只进入解释层和风险强度层，不抢核心基准计算职责。

### 2.2 初始份量权重

| 用户选择 | 初始权重 | 定义 |
|---|---:|---|
| 少一点 | 0.75 | 相对正常少约 25% |
| 正常 | 1.00 | 用户当下认知里的正常份量 |
| 多一点 | 1.25 | 相对正常多约 25% |

这三个值是初始先验，不是用户真实份量真相。

选择 `0.75 / 1.00 / 1.25` 的原因：

| 原因 | 说明 |
|---|---|
| 保守 | 避免把一次“少一点”放大成严重食欲下降 |
| 对称 | 方便构建初始相对趋势 |
| 可校准 | 后续可被完整消耗周期和多周期学习修正 |
| 不伪精确 | 没有库存闭环前只表达相对趋势 |

### 2.3 每日分品类趋势

单条喂食事件先转成 score：

```text
event_score = weight(amount_text)
```

每日分品类 score：

```text
daily_score(pet, category, date) = sum(event_score)
```

分品类建模是硬边界：

| 品类 | 是否进入趋势 | 是否形成独立基线 |
|---|---|---|
| 主粮 | 是 | 是 |
| 湿粮/罐头 | 是 | 是 |
| 零食 | 是 | 样本足够后形成频率/结构参考 |
| 营养品 | 是 | 样本足够后形成补充事实参考 |
| 其他 | 进入事实流 | 暂不进入高置信基线 |

主粮、罐头、零食、营养品不能混成一个总基线。它们的健康含义不同，混算会掩盖真实变化。

### 2.4 完整消耗周期

一次完整周期指：

```text
某只宠物使用某个储物柜食品
-> 从开始喂食到该物品被确认消耗完
-> 周期内喂食记录完整
-> 周期内没有重要异常或医疗事件影响食欲
```

完整周期输出一次周期基准：

```text
cycle_total_score = 周期内所有喂食事件 score 之和
cycle_total_grams = 消耗掉的物品总克重
cycle_grams_per_score = cycle_total_grams / cycle_total_score
cycle_daily_grams = 每日 score * cycle_grams_per_score
```

一次完整周期能可靠产生：

| 输出 | 是否可靠 |
|---|---|
| 本周期平均 score | 可靠 |
| 本周期 `grams_per_score` | 可靠度中等，依赖记录完整性 |
| 本周期日均估算克重 | 可靠度中等 |
| 本周期是否高于/低于其他周期 | 多周期后可靠 |
| 用户真实少/正常/多三档权重 | 单周期不可靠 |

### 2.5 为什么单周期不能学习三档真实权重

一个完整周期只有一个总重量约束：

```text
总重量 = 少一点次数 * 少一点克重
      + 正常次数 * 正常克重
      + 多一点次数 * 多一点克重
```

未知数至少有三个：

```text
少一点克重
正常克重
多一点克重
```

所以一个周期只能校准平均摄入尺度，不能单独反推出三档真实权重。

### 2.6 多周期权重学习

当同一只宠物拥有多个完整健康周期，且每个周期的三档分布不同，才开始学习用户真实份量权重。

推荐条件：

| 条件 | 要求 |
|---|---|
| 完整健康周期数量 | 至少 3 个 |
| 周期数据完整性 | 有开始、结束、消耗总克重 |
| 份量分布差异 | 不同周期的少/正常/多比例有明显差异 |
| 异常影响 | 无重要食欲影响；偶发异常只做标注 |
| 食品维度 | 优先同一食品或同一品类内学习 |

学习目标：

```text
找到更贴近该用户记录习惯的：
少一点权重
正常权重
多一点权重
```

约束：

| 权重 | 建议范围 |
|---|---:|
| 少一点 | 0.50 - 0.95 |
| 正常 | 固定为 1.00 |
| 多一点 | 1.05 - 1.50 |

正常固定为 `1.00`，是为了让系统只学习“少一点/多一点相对正常偏离多少”，避免基准漂移。

### 2.7 周期基准交叉验证

每个完整健康周期都会形成一个周期基准：

```text
cycle_baseline = {
  pet_id,
  food_category,
  food_item_id,
  started_at,
  ended_at,
  total_grams,
  total_score,
  grams_per_score,
  daily_average_score,
  daily_average_grams,
  amount_distribution,
  health_context
}
```

多个周期之间比较：

| 比较项 | 用途 |
|---|---|
| `grams_per_score` 变化 | 判断同一 score 对应克重是否稳定 |
| 日均 grams 变化 | 判断周期摄入量是否上升/下降 |
| 少/正常/多分布 | 判断变化是否来自用户选择结构 |
| 异常/就医标记 | 解释周期偏离原因 |
| 物品规格变化 | 区分换粮、换包装、换品类带来的影响 |

周期偏离不直接等于疾病判断。它只产生观察信号：

```text
健康周期稳定 -> 建立宠物个体摄入参考
健康周期持续下降 -> 进入观察提示
异常/医疗周期下降 -> 保留事实，用于 HIS 对照
```

### 2.8 异常事件处理

异常事件不应简单丢弃，也不应默认污染健康基准。

| 异常类型 | 处理 |
|---|---|
| 偶发、未影响食欲 | 保留标注，可进入周期但降低解释强度 |
| 明确影响食欲 | 周期不进入健康基准，进入异常对照 |
| 就医/用药/恢复期 | 不进入健康基准，进入 HIS 资料 |
| 持续异常 | 触发观察链路和就医建议流程 |

后续异常记录接入 HIS 时，需要在实验文档里新增异常批次，验证算法是否能把健康周期、异常周期、医疗周期分开。

### 2.9 置信度

| 置信度 | 条件 | 输出 |
|---|---|---|
| low | 只有模糊喂食记录 | 只展示趋势结构 |
| medium | 至少 1 个完整健康消耗周期 | 输出周期基准和估算克重 |
| high | 至少 2 个完整健康周期进入池化校准 | 输出更稳定的个体摄入参考 |
| learned | 多个周期分布差异足够 | 学习用户个体三档权重 |

当前代码实现边界：

| 能力 | 当前状态 |
|---|---|
| 60 天饮食趋势窗口 | 已实现 |
| 单个完整健康消耗周期克重校准 | 已实现，输出 `medium` |
| 多个完整健康消耗周期池化校准 | 已实现，输出 `high` |
| 多周期三档权重学习 | 未实现，仍需至少 3 个分布差异足够的完整周期后单独设计 |
| 显式消耗周期读模型 | 未实现，当前以储物柜食品 `depleted` 状态作为周期完成信号 |

## 6. 实验批次 B：两个月完整消耗周期

本批次待插入。目标是验证完整周期基准和多周期池化校准，而不是只验证趋势结构。

### 6.1 设计目标

| 目标 | 说明 |
|---|---|
| 清理批次 A | 避免旧样本干扰新周期 |
| 插入两个月喂食数据 | 模拟两个连续主粮消耗周期 |
| 绑定真实储物柜规格 | 使用 `1.5kg` 主粮作为总克重锚点 |
| 标记完整消耗 | 每个周期结束时形成一次完整物品消耗 |
| 不插入重要异常 | 先验证健康周期基准 |
| 保留后续异常扩展空间 | 下一批再加入偶发异常和持续异常 |

### 6.2 预期输入

| 周期 | 时间 | 主粮规格 | 预期事件 | 设计目的 |
|---|---|---:|---:|---|
| 周期 1 | 约 30 天 | 1500g | 每天 2 次主粮 | 形成第一个健康周期基准 |
| 周期 2 | 约 30 天 | 1500g | 每天 2 次主粮，份量分布略不同 | 与周期 1 交叉验证 |

### 6.3 预期算法表现

| 输出 | 预期 |
|---|---|
| cycle_total_score | 每个周期按模糊份量累加 |
| cycle_grams_per_score | `1500g / cycle_total_score` |
| cycle_daily_average_grams | 周期日均估算克重 |
| pooled_grams_per_score | 两个完整周期总克重 / 两个完整周期总 score |
| pooled_daily_average_grams | 两个完整周期总克重 / 两个完整周期覆盖天数 |
| calibration.confidence | 两个完整周期时输出 `high` |
| 周期对比 | 判断第二周期是否相对第一周期上升/下降 |
| 权重学习 | 两个周期仍不学习三档权重，只观察分布差异 |

正确实验样例：
