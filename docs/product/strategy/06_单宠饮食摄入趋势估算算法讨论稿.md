# 单宠饮食摄入趋势估算算法讨论稿

- 更新时间：2026-07-04
- 文档性质：产品与工程边界讨论稿
- 适用范围：单宠喂食记录、分品类摄入趋势、库存校准、健康预警、HIS 诊前资料
- 非目标：本文不是目标文档、实施计划、接口契约或医疗诊断规则。

---

## 1. 讨论结论

首期算法只解决单宠场景。多宠共用食物、分宠投喂、均分估算和共享碗模型后续单独扩展。

核心原则：

```text
用户低心智记录
-> 系统按食品品类形成单宠饮食摄入趋势
-> 健康样本足够后形成个体饮食基线
-> 有库存闭环证据后再输出克数估算
-> 异常和就医期数据单独存档，不污染健康基线
```

系统不能把“用户标记吃完一件库存”作为算法运行的硬前提。用户忘记标记时，系统仍然需要输出趋势，只是不能输出高置信克数估算。

| 层 | 是否依赖库存闭环 | 输出 |
|---|---|---|
| 分品类摄入趋势 | 否 | daily score、ratio、趋势方向、品类结构 |
| 个体健康基线 | 否 | category baseline score、样本数、样本窗口 |
| 克数估算 | 是 | grams per score、日均估算克数、置信度 |
| 健康预警 | 否 | 温和观察提醒、HIS 风险摘要 |

## 2. 首期业务边界

| 项 | 首期规则 |
|---|---|
| 宠物范围 | 单宠 |
| 食品范围 | 主粮、湿粮/罐头、零食、营养品 |
| 记录范围 | 已绑定宠物、已绑定储物柜食品或明确食品品类的喂食事件 |
| 低结构化对象 | 其他 |
| 异常期 | 不进入健康基线 |
| 医疗期 | 不进入健康基线 |
| 多宠 | 后续扩展，不进入首期算法 |

主粮、湿粮/罐头、零食、营养品都属于有业务价值的饮食事实，都应该进入宠物长期饮食趋势和 HIS 诊前资料。

关键边界是分品类建模：

| 食品品类 | 是否进入趋势 | 是否形成独立基线 | 说明 |
|---|---|---|---|
| 主粮 | 是 | 是 | 稳定性最高，是首期核心基线 |
| 湿粮/罐头 | 是 | 是 | 可反映补充摄入和食欲结构变化 |
| 零食 | 是 | 是 | 主要看频率、增减和替代主粮风险 |
| 营养品 | 是 | 是 | 主要看持续性、用量趋势和医疗上下文 |
| 其他 | 是 | 否 | 只进入事实流和低置信统计，不进入高置信量化分析 |

不同品类不能混成一个总 baseline。主粮下降、罐头上升、零食上升代表的是不同健康含义，混算会掩盖真实变化。

## 3. 低心智份量分数

用户只记录三档：

| 用户选择 | 初始分数 |
|---|---:|
| 少一点 | 0.75 |
| 正常 | 1.00 |
| 多一点 | 1.25 |

这些分数只表示相对份量，不直接声称克数。克数需要库存闭环校准后才输出。

每日分品类分数：

```text
daily_score(category) = 当天该宠物该食品品类所有喂食分数之和
```

示例：

```text
早上 主粮正常 + 晚上 主粮少一点
main_food_daily_score = 1.00 + 0.75 = 1.75

中午 湿粮/罐头正常
wet_food_daily_score = 1.00
```

## 4. 健康样本隔离

每一天的分品类饮食数据都需要带健康上下文。

| health_context | 是否进入健康基线 | 说明 |
|---|---|---|
| healthy | 是 | 正常健康窗口 |
| abnormal | 否 | 异常追踪期 |
| medical | 否 | 就医、用药、恢复相关 |
| missing | 否 | 缺少上下文或记录不足 |

异常和就医期数据不能丢弃。它们不进入健康基线，但需要进入宠物健康档案和 HIS 诊前摘要，用来解释饮食变化是否和异常、就医、用药重合。

```text
异常/就医期饮食分数
-> baseline: excluded
-> health archive: included
-> HIS pre-visit package: included
```

## 5. 个体健康基线

首期使用滚动窗口生成单宠分品类基线。

| 参数 | 建议值 |
|---|---:|
| 基线窗口 | 近 30 天 |
| 最少健康样本 | 14 天 |
| 基线统计 | rolling median |
| 趋势辅助 | EMA |
| 样本最长有效期 | 近 180 天 |

基线生成：

```text
healthy_scores(category) = 近 30 天内 included_in_baseline = true 的 daily_score(category)
sample_count < 14:
    baseline(category) = None
sample_count >= 14:
    baseline(category) = median(healthy_scores(category))
```

采用中位数作为首期主基线，原因是它更抗偶发波动。例如某一天少吃或多吃，不会明显拖动个体基线。

EMA 只用于趋势方向，不直接替代基线：

```text
ema_today = alpha * score_today + (1 - alpha) * ema_yesterday
```

建议 alpha 初始取 0.25。

## 6. 食欲偏离计算

当 baseline 存在时：

```text
ratio(category) = daily_score(category) / baseline_score(category)
drop = 1 - ratio
```

| ratio | 含义 |
|---|---|
| 接近 1.0 | 接近该宠物自身健康习惯 |
| 小于 1.0 | 低于自身基线 |
| 大于 1.0 | 高于自身基线 |

首期不因单日偏低触发风险。需要连续窗口判断。

建议分层：

| 条件 | 输出 |
|---|---|
| 样本不足 | 只展示记录，不做分析 |
| 单日偏低 | 只作为趋势点 |
| 近 7 天多数偏低 | 轻提示 |
| 近 14 天多数偏低 | 观察卡片 |
| 叠加异常、老年、体重下降 | 引导关注或就医 |

预警文案必须保持观察和建议语气，不能写成诊断结论。

## 7. 天气与年龄因子

天气和年龄不直接改写 daily_score，也不直接改写 baseline。它们只影响阈值、提示强度和解释文案。

| 因子 | 用法 |
|---|---|
| 高温 | 食欲下降时降低预警强度，提示可能与天气有关 |
| 老年宠 | 对持续下降更敏感，阈值收紧 |
| 幼宠 | 对长期下降敏感，对短期波动保守解释 |
| 普通成年宠 | 使用默认阈值 |

首期不写死全国统一温度规则。城市室外温度、室内空调、湿度和地区差异都会影响真实食欲表现。

可以先设内部初始阈值：

| 场景 | 连续偏低阈值 |
|---|---:|
| 默认 | drop >= 25% |
| 高温 | drop >= 35% |
| 老年宠 | drop >= 18% |

这些阈值属于产品参数，后续需要通过真实数据校准。

## 8. 库存克数校准

库存数据只负责把相对分数校准成克数。它不是饮食趋势运行的必要条件。

无库存闭环时：

```text
confidence = low
grams_per_score = None
daily_grams = None
输出趋势，不输出克数
```

有一件库存闭环时：

```text
total_score = 该库存消耗周期内对应食品品类的所有 included daily_score 之和
grams_per_score = package_weight_grams / total_score
daily_grams = daily_score * grams_per_score
confidence = medium
```

多次稳定闭环后：

```text
confidence = high
grams_per_score = 多个周期的稳健估计
```

首期不默认引入损耗系数。损耗、受潮、漏洒、被其他宠物吃掉都属于后续校准参数，不能用一个固定值制造伪精确。

## 9. 置信度

| 置信度 | 条件 | 输出限制 |
|---|---|---|
| low | 无库存闭环，只有份量记录 | 只展示趋势和相对偏离 |
| medium | 至少一次完整库存闭环 | 可展示估算克数，标注仅供参考 |
| high | 多次闭环且波动稳定 | 可展示更稳定的日均克数区间 |

页面需要明确表达：

```text
这是基于喂食记录和库存数据的估算，不是精准称重。
```

## 11. 前端展示建议

食品详情页应表达四类信息：

| 模块 | 展示内容 |
|---|---|
| 当前食品 | 图片、规格、状态、首次喂食时间、食品品类 |
| 喂食趋势 | daily score、baseline、EMA 趋势 |
| 估算消耗 | 当前置信度、估算日均克数、剩余周期 |
| 健康观察 | 连续偏低、异常期重合、就医建议 |

没有库存闭环时，页面仍然展示趋势，不展示克数。

```text
当前可分析：饮食摄入趋势
暂不可分析：克数估算
原因：还没有形成该库存的消耗闭环
```

## 12. HIS 联动边界

HIS 和诊前资料包需要看到完整事实，而不是只看健康基线。

| 数据 | HIS 用途 |
|---|---|
| 健康基线 | 了解该宠物平时各类饮食摄入水平 |
| 食欲下降窗口 | 观察异常开始前后是否有变化 |
| 异常/就医期分数 | 对照症状和治疗过程 |
| 库存校准置信度 | 判断克数估算可靠程度 |
| 记录缺口 | 医生知道哪些结论证据不足 |

医疗表达必须标注：

```text
饮食摄入趋势仅供医生参考，不构成诊断结论。
```

## 13. 多宠后续扩展

多宠不进入首期。后续需要单独设计：

| 问题 | 后续方向 |
|---|---|
| 多宠共用同一库存 | 共享消耗模型，置信度自动降低 |
| 分宠喂食 | 喂食记录支持选择单只或多只宠物 |
| 共用碗 | 只能输出家庭级消耗趋势，不能伪造单宠精确克数 |
| 多宠均分 | 只能作为低置信估算，不作为默认高置信结论 |
| 多宠 HIS | 必须区分单宠事实和家庭共享事实 |

后续多宠算法必须遵循同一原则：

```text
没有明确归属的摄入，不能当成单宠强事实。
```

## 14. Python 模拟结论

模拟结果验证了分层逻辑：

| 场景 | 结果 |
|---|---|
| 1-14 天 | 样本不足，不生成基线 |
| 约 30 天健康样本 | 生成首版 baseline |
| 高温期轻微下降 | 不直接误报 |
| abnormal / medical 期 | 不进入健康基线，进入健康档案 |
| 恢复后长期偏低 | baseline 逐步自适应 |
| 无吃完标记 | 趋势可跑，克数不输出 |
| 有一次库存闭环 | 输出 medium 置信克数估算 |

关键结论：

```text
趋势永远可跑，克数看证据，异常期保留但不污染健康基线。
```
