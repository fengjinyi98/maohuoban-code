# 宠物档案号编码规则

## 定位

宠物档案号是毛伙伴为每只宠物生成的平台内唯一身份编码。它用于覆盖没有植入芯片的宠物档案识别场景，并为后续自有芯片体系预留统一编码空间。

宠物档案号不同于芯片号：

| 标识 | 用途 | 生成方 | 是否可修改 |
|---|---|---|---|
| 宠物档案号 | 平台内唯一识别宠物档案 | 后端创建宠物档案时生成 | 不可修改 |
| 芯片号 | 已植入宠物芯片的官方识别编码 | 用户录入，后端校验 | 首次添加后锁定，修改走申诉 |
| 毛伙伴号 | 平台内唯一识别用户账号 | 后端创建用户账号时生成 | 按用户账号规则处理 |

## 16 位编码结构

宠物档案号使用 16 位纯数字编码，展示时按段分隔。

示例：

```text
9011562600000019
901-156-26-0000001-9
```

| 段 | 位数 | 示例 | 含义 |
|---|---:|---|---|
| 平台前缀 | 1 | `9` | 毛伙伴自有身份体系 |
| 类型码 | 2 | `01` | `01` 表示宠物档案号 |
| 国家/地区码 | 3 | `156` | 参考 ISO 3166 数字码，中国为 `156` |
| 签发年份 | 2 | `26` | 2026 年签发 |
| 序列号 | 7 | `0000001` | 当前类型 + 地区 + 年份下的递增序列 |
| 校验位 | 1 | `9` | Luhn / Mod 10 校验位，降低输错概率 |

## 类型码预留

| 类型码 | 含义 |
|---|---|
| `01` | 宠物档案号 |
| `02` | 平台自有芯片号 |
| `03` | 救助/流浪动物临时身份 |
| `04` | 繁育/交易来源身份 |

## 容量

7 位序列号支持每个「类型 + 国家/地区 + 年份」下最多 10,000,000 个编码。

| 范围 | 容量 |
|---|---:|
| 中国区宠物档案号单年容量 | 1000 万 |
| 中国区宠物档案号 10 年容量 | 1 亿 |
| 单国家/地区每个类型单年容量 | 1000 万 |

## 唯一性策略

宠物档案号必须由后端生成，前端只展示和消费。

推荐后端生成流程：

```text
key = pet_code_seq:{type}:{region}:{year}
sequence = atomic_increment(key)
body = prefix + type + region + year + sequence.padStart(7, "0")
check_digit = luhn(body)
code = body + check_digit
```

唯一性由两层保证：

| 层 | 策略 |
|---|---|
| 分配器 | 按 `type + region + year` 原子递增 |
| 数据库 | `pet_profile_code` 建唯一索引 |

并发实现可选：

| 方案 | 说明 |
|---|---|
| PostgreSQL sequence | 强一致，适合主库生成 |
| Redis INCR | 高吞吐，需要持久化和回源兜底 |
| PostgreSQL advisory lock | 适合按段加锁生成 |

数据库唯一索引用于兜底防止迁移、人工导入或异常重试造成重复。发生唯一冲突时后端重新取号。

## 前端展示规则

| 场景 | 展示 |
|---|---|
| 编辑资料页 | 展示格式化档案号，例如 `901-156-26-0000001-9` |
| 点击档案号 | 弹出说明，解释平台内唯一身份编码 |
| 编辑能力 | 不提供编辑入口 |
| 搜索输入 | 可支持带分隔符或纯数字输入 |

说明文案：

```text
宠物档案号是毛伙伴为每只宠物生成的平台内唯一身份编码。它不是芯片号，不需要植入芯片，也不可自行修改。
```

## 后端落地要求

| 字段 | 要求 |
|---|---|
| `pet_profile_code` | 16 位纯数字，唯一，非空 |
| `microchip_number` | 可空，15 位纯数字，非空时全局唯一 |
| 创建宠物 | 必须同步生成 `pet_profile_code` |
| 更新宠物 | 禁止普通接口修改 `pet_profile_code` |
| 申诉流程 | 只处理芯片号错误，不处理档案号重写 |
