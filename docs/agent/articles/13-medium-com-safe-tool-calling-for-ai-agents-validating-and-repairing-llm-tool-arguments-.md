In the last post, we built a state machine to take control of our agent’s logic. That gave us a system where every decision is traceable, something we can actually debug. But agents don’t just think; they do. They call APIs, query databases, and interact with external systems. And this is where things get hard to manage

You’ve probably seen it. You built an agent you think that is really cool, and it works great, until it decides to call your search_flights tool with date: "next Tuesday" instead of a proper ISO date. The API throws an error and the whole run collapses.

This is something you can’t fix in the prompt. We’re treating our tools like suggestions, hoping the LLM figures it out. The real solution is to treat tool calls with the same discipline we use for any other API integration: with strict contracts, validation, and a clear plan for when things go wrong.
